# 编写面试题库与扩展包

2026-10-19。格式版本 `schemaVersion: 1`。正式游戏已经启用多轮面试：18 个组织、34 个岗位题库、106 道题。题目是同人情境设计，不是官方招聘原文。

## 先运行一个扩展包

从项目根目录运行：

```bash
node tools/validate-interview-pack.mjs docs/examples/dlc-blacksteel-interviews.json
node tools/verify-interviews.mjs
```

第一条验证[可运行的黑钢题库扩展示例](examples/dlc-blacksteel-interviews.json)，把一题添加到两个现有岗位池。它仅在验证进程中注册，不自动安装进游戏。第二条检查正式题库、评分和会话流程。

编辑器可关联 [JSON Schema](../schemas/interview-pack.schema.json)。JSON Schema 检查字段、类型、范围；命令行还检查组织/路线引用、维度一致、权重总和、重复 ID、抽题数量等跨字段约束。新增维度时需要同步 `TL.INTERVIEW_AXES` 与 Schema，不能只在题目中拼一个新名字。

游戏保持普通 `<script>` 加载，可直接双击 `index.html` 运行。发布题库包时，把经过验证的 JSON 数据作为对象传给 `TL.registerInterviewPack(pack)`，包装成单独 JS 文件并在核心 `js/engine/interview.js` 之后加载。不要在 `file://` 下依赖 `fetch()` 自动读取 JSON。本轮实现了题库注册接口，尚未实现玩家可操作的 DLC 安装器、开关或下载器。

## 装载一份扩展包文档

`TL.loadInterviewPacks(document)` 接受三种形态：单个包对象、`{packs: [...]}`、或直接是数组；也接受 JSON 字符串。
它只做"解析 → 逐个交给注册器 → 收集失败"，**校验的唯一来源仍是 `TL.registerInterviewPack`**：

- 一个包被拒不会影响同批次其他包，也不会留下半注册状态（注册器先全量校验再改动注册表）。
- 失败按 `packs[i]` 定位并带 `pack.invalid` / `pack.not-object` / `pack.json-invalid` 三类码。
- 池的归属属于**声明它的包**（`pack.pools`）；扩展包（`extensions`）只往既有池里加题，不改变归属，
  因此会话的 `session.pack` 记的是声明包，而存档的内容锁会同时列出核心包与扩展包。

内容锁与存档的关系见[存档版本协议](存档版本协议.md)：一旦某局用到了扩展包的题目，存档就会把该包记进
`contentLock.packages`；在读不到该包（或版本/内容变了）的构建上，读档会被拒绝并给出具体是哪一个包。

## 玩家流程和判定

招募邀请 → 3 道组织题（从 4 道中无重复抽取）→ 1 道岗位题 → 结果页 → 继续人生。题目与回答顺序使用项目种子随机数，结果页确认前时间保持暂停。所有题目都答完后统一评分，不在答对某一题时直接发放职业。

每组织统一三项倾向，例如莱茵生命采用研究方法、职业伦理、团队协作；近卫局采用纪律意识、公众保护、临场判断。不同岗位有各自的专属题。每个选项对三项倾向分别给 0–3 分，全部题目只影响面试倾向，不扣健康、不触发死亡、不修改财富。

对每一项倾向：`倾向百分分 = 回答所得分之和 ÷ 本卷各题该项最高可得分之和 × 100`。综合分为三项百分分的加权和。目前权重依次为 0.40、0.35、0.25，各项下限均为 40；综合 ≥60 且所有倾向达标则录用，否则综合 ≥45 列为候补，其余未通过。比较时使用未四舍五入的数值，界面保留一位小数。可以通过不同组合达到要求，不设“唯一答案序列”；录用后不再追加概率抽签。

候补一年后可重新申请；未通过和主动撤回三年后可重新申请。候补不会自动录用。资格变化或题目暂不可用不加额外面试冷却，但原招募事件仍有自己的冷却和次数限制。

罗德岛原招募事件、毕业选项、整合运动邀请、历史转职与一般岗位转任均已接入。申请期间保留旧职；成功才交接，未通过或撤回保留旧合同。巴别塔等已解体组织不因此恢复：转职未成功后会重新要求选择去向。罗德岛录用后才分配符合技艺门槛的干员职业，整合运动的训练加成也只在加入时兑现。

## 包格式

### 非企业组织的前置约束

问答引擎可复用，但不能把所有加入方式写成企业招聘。组织定义的 `admission` 可设置问答标题（例如“营地接纳”“家族试探”）；缺省为“面试”。资格校验仍在开始、答题和最终加入时执行。

- 整合题库只服务 1094—1095 的乌萨斯旧营地路线，需要真实接触旗标 `reunionContactYear`。不能把这些互助问题用于 1096 年攻城派系或九领导的后继组织。
- 家族问答必须经过引荐（`sirFamilyIntroducedYear`）；1099 年起，`locationAllowed` 阻止新沃尔西尼的家族活动。不得把新城禁令扩大到全叙拉古。
- `unpaid` 与 `subsistence` 位于组织 JS 定义，分别控制无固定工资和年度实物补给系数；题库 JSON 无权更改收入、年份、资格或世界状态。完整资料与玩法边界见[设定核查](整合运动与家族设定核查.md)。

顶层除下表外不允许额外字段。格式规则由 `js/engine/interview.js` 的 `validateInterviewPack()` 执行；校验失败不注册任何一部分数据。

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `id` | 是 | 全局唯一、小写字母开头，只含小写字母、数字和下划线；建议 `dlc_<主题>_<内容>` |
| `schemaVersion` | 是 | 固定为 1；改变字段语义需要升级格式与迁移逻辑 |
| `version` | 是 | 正整数，表示内容版本；同一运行期不能用相同 ID 覆盖已经注册的包 |
| `sourceType` | 是 | 固定 `project-rule`，表示题目和评分属于同人游戏规则 |
| `questions` | 是 | 新题目数组，可为空；每道新题都必须被某个题库引用 |
| `pools` | 是 | 新岗位题库数组，可为空；不能覆盖现有题库 ID |
| `extensions` | 否 | 向现有题库追加题目引用的数组；同一包每个目标池只能出现一次 |

新增包不得改变既有 ID 的含义。更新同一发行包需在下次加载时替换内容文件并增加 `version`，不能在已运行游戏中第二次注册同名包。正在面试的角色保存独立题目与规则快照，之后加载的扩展题不会改变这张试卷。

## 题目与选项

| 字段 | 约束 |
| --- | --- |
| `id` | 全局唯一稳定 ID，格式同包 ID；旧题退役不复用 ID |
| `organization` | 必须是已存在的组织 ID |
| `kind` | `organization` 或 `role` |
| `route` | 岗位题必填且必须存在；组织题禁止填写 |
| `prompt` | 非空纯文本，最多 500 字符，不写 HTML、脚本或 Markdown 链接 |
| `options` | 2–4 个回答；撤回按钮由引擎添加，不写入数据 |
| `fromYear` / `untilYear` | 可选整数，含起止年份，起点不得晚于终点；都不填表示不额外限制 |

每个回答仅允许 `id`、`label`、`scores`。`id` 在本题内唯一；`label` 是最多 140 字符的非空纯文本；`scores` 必须恰好包含目标题库的三项维度，每项为 0–3 的整数。每道题在每个维度至少有一个选项能得正分，避免零分母。

题面要描述具体处境与取舍，选项要描述角色会做的行为。不要让玩家背 PRTS 百科年份，不把现实属性不足伪装成选错答案，也不声称某位原作人物必然担任面试官。若使用历史人物或事件，题目出场窗必须与组织和人物在场窗一致，另在资料说明中记录原文依据。

公共题可以被同组织多个岗位共用，但必须使用相同三项倾向；岗位题仅能进入自身岗位池。跨组织题目引用、未知维度、拼写错误、重复选项和重复引用都会拒绝注册。

## 岗位题库与扩展

| 字段 | 约束 |
| --- | --- |
| `id` | 必须等于目标路线的 `interview.questionPool` |
| `organization` / `route` | 指向已存在路线 |
| `axes` | 恰好三项，不重复，集合与路线 `interview.axes` 一致 |
| `axes[].id` | 来自 `TL.INTERVIEW_AXES` 的维度 ID |
| `axes[].weight` | 0.01–1，三项总和为 1（浮点容差 1e-8） |
| `axes[].minimum` | 0–100，该项录用下限 |
| `questionIds` | 不重复的题目 ID 数组；引用必须存在且属于正确组织/岗位 |
| `draw.organization` | 2–5 的整数；当前正式池为 3 |
| `draw.role` | 固定为 1；支持多道岗位题中抽一道 |
| `passScore` | 1–100 |
| `waitlistScore` | ≥0 且不大于 `passScore - 1` |

`extensions` 的每项只能包含 `pool` 和非空 `questionIds`；目标池必须已注册。它只追加题目，不偷偷修改权重、阈值或招募门槛。需要改变规则时，应发布明确的版本变更与平衡说明。

静态校验保证总题数足够。按年份筛选后若不足，引擎显示暂缓并结束申请，不会退回随机录用，也不会把玩家卡在没有选项的弹窗。发布前必须覆盖所有有效年代窗，确保不会经常出现这种情况。

## 会话接口

| 接口 | 用法与结果 |
| --- | --- |
| `tryJoinOrganization(S, id, route, context?)` | 新申请入口，返回 `interview / ineligible / busy / unavailable` 等状态；不是录用布尔值 |
| `beginOrganizationInterview(...)` | 资格检查后创建当前申请，保存 token、年份、原组织/路线及面试快照 |
| `answerOrganizationInterview(S, token, questionId, optionId)` | 只记录当前题的一次有效答案，返回布尔值；抉择层负责随后推进 |
| `evaluateOrganizationInterview(application)` | 无副作用地计算 `incomplete / passed / waitlisted / rejected`、分项和综合分 |
| `continueOrganizationInterview(S)` | 没有其他待处理抉择时展示当前题或结果；正常由 `afterDecision` 调用 |
| `finishOrganizationInterview(S, withdrawn?)` | 完成/撤回、复核资格、记录结果；不完整面试不能结算 |
| `completeOrganizationInterview(S, {token,status})` | 底层录用兑现接口；正式会话必须与实际评分一致，不能提前传 `passed` 跳过题目 |
| `registerInterviewPack(pack)` | 原子校验并注册题库包；出错抛出 `Interview format: ...` |

`context` 普通招募可省略；内部转任使用 `{transfer:true, source:'career'}`，历史转任还带 `transitionId`。转任标记由组织系统生成，不允许题目选项自行写入。跨年、人生结束、退休、所在地变化、学历/职业资格变化、面谈期间接受其他组织任职等会导致重新核验失败，不会误录用。

`S.orgApplication.session` 保存本卷快照与答案，`S.orgInterviewHistory` 保存结果，人生报告复制历史。token 只在角色内部递增，不是跨角色安全凭证。当前项目保存的是人生结果，尚未提供完整人生中途存档恢复；不要把可序列化面试数据当作已经实现全局续玩。

不要从题目调用 `joinOrganization()`，不要覆盖 `TL.afterDecision`，也不要在旧题的 `run()` 中直接打开下一题。需要扩展钩子时调用原钩子并保留后续推进。关闭适配器仍保留给低层测试使用，但正式页面总是安装多题适配器。

## 组织 DLC 的共同边界

组织、路线、人物、事件、题目均使用稳定 ID 与包前缀。新组织必须先注册组织/职业/地区引用，再注册题库；目前的组织工作事件和年表仍用现有 JS 数据结构，不能仅放入 JSON 就声称整个组织已可玩。

每个组织包应交付招募条件、至少一条晋升路线、专属工作事件、退出/转职、历史停止/重组规则、人物互动窗、面试池及资料说明。组织“存在”、招募“开放”和人物“在场”是三个不同条件，不能混用一个年份。

路线阶级、工资、试题和得分须标注游戏规则；资料来源应记录 PRTS 条目、对应剧情/页面、核对日期及不确定项。接入普通抉择、自动模式、移动端、日志和人生报告后才能算作完成 DLC。具体拆包与验收范围见[DLC 更新计划](组织DLC更新计划.md)。

# 事件效果契约

事件处理器过去直接改共享状态：`S.job = 'seeking'`、`S.flags.x++`、`TL.eff(S, {...})` 混在一起。
本契约把"内容要造成什么变化"变成**可校验的数据**，由一个函数统一执行。

代码：`src/model/effects.ts`；运行时入口：`TL.applyEffects(state, effects)`、`TL.validateEffects(effects)`；
回归：`tests/event-effects.test.mjs`。

## 允许的效果（白名单）

| `kind` | 字段 | 说明 |
| --- | --- | --- |
| `attributes` | `hl` `h` `sm` `so` `arts`（任选，有限数） | 经模型自身的属性规则结算（含 0–100 钳制） |
| `money` | `amount` | 现金增减，单位与既有事件一致 |
| `flag` | `name`、`delta?`（默认 1） | 数值旗标自增；缺失视为 0 |
| `setFlag` | `name`、`value`（JSON 原始值） | 直接写入旗标 |

**故意不提供**：改职业、加入/离开组织、退休、感染、派发事件、写随机数。
这些必须走各自的转换入口（`dismissFromJob` / `enterCoercedLabour` / `joinOrganization` …），
所以内容作者无法用"效果"绕过雇佣政策或不变量。

## 校验规则

整份列表**先全量校验，再逐条应用**；任一条不合法就整份拒绝、状态零改动。诊断带稳定码：

`effects.not-array`、`effects.empty`、`effect.not-object`、`effect.unknown-kind`、
`effect.unknown-property`、`effect.unknown-attribute`、`effect.empty-attributes`、
`effect.non-finite`、`effect.empty-flag-name`、`effect.invalid-flag-value`。

`effect.unknown-property` 是刻意加的：`{kind:'attributes', helth:3}` 这种拼写错误会当场失败，
而不是静默变成"没有效果"。

## 迁移一个事件的标准流程

1. 先用 `tools/capture-event-baseline.mjs` 抓迁移前的行为：
   ```bash
   node tools/capture-event-baseline.mjs tests/fixtures/event-effects-baseline.json <eventId...>
   ```
   夹具记录固定种子下的 `run()` 返回文本、完整状态 JSON 与后续 8 次随机数。
2. 把 `TL.eff(S, {...})` 改写成 `TL.applyEffects(S, [{kind:'attributes', ...}])`，
   保持**顺序与数值完全不变**（效果在文本/`TL.pick` 之前应用）。
3. 在 `tests/event-effects.test.mjs` 的基线列表中加入该事件，断言文本、状态与随机流逐字节一致。
   若事件包含 `TL.pick` 等随机文本，顺序不变则随机流不变。

已迁移 **52 个**事件（`node tools/scan-effects-migration.mjs` 可随时列出"还能迁但还没迁"的清单，当前为 0）。
第一批手工迁移 11 个；余下 41 个用 `tools/migrate-effects.mjs` 批量改写，仍逐条比对基线夹具。
其中 5 个事件的 `TL.eff` 同时带现金，由 `--repair` 拆成 `attributes` + `money` 两个效果（现金不参与属性钳制）。

选型规则（扫描器实现的就是这三条）：`run` 内只有"属性/现金/旗标 + 固定或 `TL.pick` 文本"才可迁移；
任何 `S.x.y =` / `S.x[k] =` / `push` / `splice` / 排序、读写 `queue`/`pending`、
或调用 `TL.die`、职业与组织写入等非纯函数，都留在 legacy。`illness`（写 `S.conds[k]`）、
`arts_awaken`（写旗标）、`job_promote`（改 `opRank`）就是这样被排除的。

工具链：

```bash
node tools/scan-effects-migration.mjs           # 列出可迁移清单（只读）
node tools/capture-event-baseline.mjs <out.json> <id...>   # 迁移前抓基线
node tools/migrate-effects.mjs --write <id...>  # 机械改写（默认 dry run）
node --test tests/event-effects.test.mjs        # 逐字节等价断言
```

## 现状边界

- 迁移是**逐个事件**的，其余事件仍可直接写 `S`。这是有意的：一次改一个、每次都有等价证明，
  比一次性重写 150 个事件安全。
- `TL.applyEffects` 本身是"校验后的顺序写入"，不带回滚；**调度层**已经提供回滚
  （见下节），所以事件抛错不会留下半次修改。
- 效果列表无法表达"条件分支内的效果"；这类事件先保留 legacy 写法，等条件也变成数据化谓词再迁移。

## 调度层的失败回滚

`src/kernel/events.ts` 的 `fire()` 现在把每次派发当作草稿执行：

1. 派发前做整份状态 JSON 快照 + 随机游标（仅当没有待决抉择时；有 `pending` 时闭包无法快照，
   声明为不可回滚而不是假装成功）。
2. 内容抛错 → 用快照就地还原 `state`（同一对象、所有键重建），并把随机流回卷到派发前位置。
3. 失败信息带 `rollback: 'full' | 'state-only' | 'none'`，经 `error` 端口上报（浏览器为 `console.error`）。
4. 回滚后的派发**不**再执行组织同步（`sync`），避免把同一动作应用两次。
5. 失败事件不计数、不写 `evCount`/`flags`/`recent`。

代价：每次派发一次 JSON 往返，实测 1000 局完整人生 24s → 42s（约 42ms/局），分布完全不变。
在状态规模或性能需要时再换成字段级日志，但**不能**降级为"失败后继续跑"。

测试：`tests/event-transaction.test.mjs`（内核 + 真实运行时两套），覆盖部分写入回滚、
随机流回卷、无随机钩子时的 `state-only`、待决抉择时的 `none`、成功事件仍正常提交。

# 工程化实施路线

日期：2026-10-20。目标架构见[工程化架构决策](工程化架构决策-2026-10-20.md)。以下均为待实施阶段；当前审查只完成设计与现状验证。

## 实施原则

每阶段交付能运行、能回归、能独立撤回的版本。先保证迁移前后规则一致，再修改病程或随机抽样。现有 UI、固定种子、组织任职和面试路径是迁移约束。

建议优先完成 M0–M3，再用 DLC 01 做首次扩展验收。矿石病 v2 可在 M2 建立健康端口后独立推进，不需要等待所有 DLC；正式合入时必须通过自己的平衡与边界检查。

## M0：建立工程入口与可复现基线

**交付**

- 增加 `package.json`、锁文件、明确的 Node 支持范围及开发/校验命令。实施时选择兼容版本并锁定，不能依赖开发者机器上的全局库。
- 接入 TypeScript、Vite 与新源码严格检查；JS 暂存 legacy 范围，逐文件启用 `checkJs`/JSDoc。原生 DOM/Canvas 保留。
- 整理浏览器和无头模式的共同加载清单，消除 `headless.mjs` 重复加载项；后续 ESM 模块统一由 `bootstrap` 装配。
- 固定 89055db 的行为样本：出生、面试、转任、晋升、退休、感染、死亡、快转、长生种；记录规则版本、种子、重心时间与选择。
- 建立新旧实现的回放摘要对照，保留旧 VM 作为迁移期参照，验证记录不只含最终寿命，还包括事件/决策顺序和 RNG 游标。
- CI 在部署前运行现有结构及专项检查；之后接入 `typecheck`、内容校验、构建和浏览器冒烟。

**验收**

全新 checkout 按文档安装即可运行；开发和生产静态页面可用；现有检查全过；同一基线回放结果一致；GitHub Pages 子路径资源可用。若继续发行离线包，双击打开也单独通过验收。

**回退**

保留原脚本入口与原 Pages 装配产物，直到新构建验收。此阶段不调整任何模型参数。

## M1：独立模拟实例与命令入口

**交付**

- 提取 rng/数学工具，定义实例 RNG，增加 `snapshot/restore`；保持旧随机算法和抽样顺序。
- 建立 `createSimulation(registry, config, rng)`，状态不再依赖 `TL.S`；多个模拟可以在同一进程中交错推进。
- 应用层统一处理开始人生、选择重心、选择选项、自动模式和推进请求；UI 不直接改模拟状态。
- 将播放控制与模拟年内时间分开；命令携带会话 ID、修订号和稳定选项 ID。
- legacy 桥接明确范围；迁移模块只能通过新入口访问旧实现，禁止新代码继续扩展 `window.TL`。

**验收**

两个固定种子模拟交错推进，与各自单独运行的结果一致；出生动画/渲染不改变 RNG；快转在抉择和死亡处停止；重复按钮或过期答案不重复生效。

**回退**

应用层切回旧引擎适配器，旧版不会读取新版进行中快照。已有死亡摘要继续可读。

## M2：领域边界与年度管线

**交付**

| 旧位置 | 迁移目标 | 必须保留的语义 |
| --- | --- | --- |
| `state.js` / `year.js` 的收入、收支 | economy | 月收入 × 12、补给与现金分开、养老金不重复乘倍率 |
| `organization.js` | organizations + 明确转换服务 | 申请/录用复核、同年不重复晋升、离职履历闭合 |
| `oripathy.js` / `lifetable.js` | health + mortality | 先封装原 v1 规则，保持现有终末与归因行为 |
| `data/events.js` 的排程 | kernel scheduler + 内容定义 | 保持现有事件预算，组织机会占用原事件位 |
| `data/timeline.js` | history + 内容定义 | 世界修正、地域影响、个人遭遇分开，效果不重复 |
| `decision.js` / `interview.js` | interaction + interviews | 试卷快照、答题顺序、结果解释和退出语义 |
| `year.js` 的报告 | 报告投影与 application | 历史快照与当前工资口径分开，报告只读取结果 |

- 将 `protectedEvents` 逐步提升为职业变更、扣薪、医疗安置等动作的政策校验；新 DLC 的事件 ID 不能绕过保护。
- 用语义化退出原因替代以中文“退休”字符串驱动业务，显示文本独立。
- 查询函数不隐式改变任职；跨领域转换统一提交。
- 将 `pending._def/_opts` 换成可序列化的定义/选项引用和会话快照。多轮互动由统一仲裁器推进。
- 事件草稿、RNG、队列、日志、冷却和次数必须同事务提交；错误暂停并留下诊断。

**验收**

原有所有组织/面试/势力测试继续通过；年度快照工资等于本年收支使用的工资；退休权益只创建一次；失败事件对状态和 RNG 零残留；直接事件死亡与年度死亡不会重复结束人生。

**回退**

按领域保留旧适配器；一次 PR 只迁移一个边界或一条事务路径。改变行为的修复单独记录，不能藏在文件搬迁中。

## M3：内容注册器与首个完整插件样本

**交付**

- manifest、版本解析、依赖排序、原子注册、所有权、重复 ID、引用/时间窗校验和内容锁。
- 同一份 schema 支持编辑器提示及运行时字段校验；跨实体规则集中由内容验证器执行，避免维护互相漂移的两套字段定义。
- 核心内容经过注册器；派生组织列表、年表索引及缓存一次生成并冻结。
- 支持 `adds` 与有限 `extends`，拒绝静默覆盖；保留旧题包 schema/ID 的适配器。
- 玩家在新局配置中选择启用包；运行中的人生固定包集合，关闭依赖包时给出明确原因。
- 将现有黑钢题库示例转成外层清单样本，再加最小组织任务链，验证组织/事件/题库的完整接线。
- 对新格式分离纯条件与随机机会；旧随机条件保留在 legacy 格式，改变抽样语义时单独升级规则版本。

**验收**

空包、纯追加、新组织、缺依赖、版本不符、依赖环、ID 冲突、同字段补丁冲突、错误年份、无出路任务和缺题均有明确结果。失败装载不污染任何注册表。冻结后尝试写入被拒绝；同一内容锁与命令记录可复现。

样本 DLC 的变更应集中于包目录、包索引/构建清单和自身测试；若每加一个组织仍要编辑通用 `year.js` 或引擎 `switch`，本阶段不算完成。

## M4A：矿石病 v2

依赖 M2 的 health/mortality/economy 边界；可以与 M3 内容注册工作分支并行开发，但不要求并行代理或同时改同一份核心文件。

**交付**

- 全角色健康状态、暴露、双指标、真实值与检测值、症状/器官画像、诊断和信息公开分离。
- 固定步长推进、分期滞后、治疗计划和经济结算；不引入本项目已排除的阿戈尔失水/保湿惩罚。
- v1/v2 明确规则版本；迁移旧事件的 `stage/treated/known/crystal` 读写，UI 和报告改读统一视图。
- 唯一死亡聚合入口，移除 v2 中旧结晶率硬阈值与旧倍率的重复作用。
- 精确记录模型参数为项目规则；病例资料只提供建模约束，不声称概率已获官方证实。

**验收**

提案的六项不变量，加上“确诊不等于公开”“渲染不影响病程”“一次治疗不重复扣费”“检测误差不反写真实值”“失效工作资格按雇佣政策处理”。覆盖高融合低血液、高血液低融合、治疗后反弹和临床分期滞后。

固定种子批量对比 v1/v2 的感染率、感染后生存期、死因、治疗覆盖和费用，按地区/职业/阶层分层。变化是明确规则变更，不要求逐局与 v1 相同；异常阈值和可接受区间在生成结果前固定。

## M4B：DLC 内容深化

依赖 M3。保持现有 DLC 01–05 顺序和设定边界，按实际需求逐步加入 quests/relationships，不提前实现无限通用任务编辑器。

**首包完成标准**

- 深化现有黑钢/雷神而非重复建组织；每条受影响路线有完整任务、晋升、离职和历史变化。
- 内容、规则来源和纯项目制度分别标注；人物实际出场窗口单独验证。
- 包开关、依赖报错、实际招募、全部面试结果、任务失败/取消/完成及自动模式均可走通。
- 320/390/1440 宽度下真实点击、长题滚动与报告展示通过。
- 运行至少 1000 局固定样本加构造状态场景。自然样本没出现不等于不可达，构造可达也不等于自然概率合理。

## M5：中途存档与发行加固

仅在新状态和交互都可序列化后开始。

**交付**

- 版本信封、内容锁、随机状态、队列、试卷/任务快照和命令游标；存储采用应用端口，摘要与完整存档分开。
- 支持未结束年度、面试中、任务等待中、退休转折后等保存点；拒绝在事务未提交时保存。
- 每次迁移在副本上执行，失败保留原件；缺 DLC 不静默丢弃数据。
- 错误诊断记录规则/包版本、种子、命令位置、事件来源；无头模式提供严格失败输出。
- 发布产物验证、部署前所有关卡、离线发行（若继续承诺）及旧摘要兼容检查。

**验收**

“连续运行”与“保存 → 关闭 → 恢复 → 继续”的规范化状态、事件序列、RNG 状态相同。读取旧摘要成功；未知版本、损坏数据、缺包和迁移失败均不覆写原件。

## 发布关卡与完成定义

目标 CI：安装锁定依赖 → 类型与依赖边界检查 → 内容校验 → 单元/契约/既有回归 → 固定场景及分布报告 → 生产构建 → 浏览器冒烟 → 部署。批量模拟和完整内容矩阵可按变更范围在 PR 或发行关卡执行；不能只运行构建。

“工程化完成”的判断应是：新增普通组织 DLC 不改模拟内核；新增健康模型只实现健康/风险契约；UI 更换不改变模拟结果；同一进程多个实例互不干扰；注册失败和事件失败不会留下半次修改；相同内容锁、规则版本与输入可复现。目录变多或 `.js` 改为 `.ts` 本身不构成完成。

# 工程化实施路线

日期：2026-10-20。目标架构见[工程化架构决策](工程化架构决策-2026-10-20.md)。以下均为待实施阶段；当前审查只完成设计与现状验证。

## 实施原则

每阶段交付能运行、能回归、能独立撤回的版本。先保证迁移前后规则一致，再修改病程或随机抽样。现有 UI、固定种子、组织任职和面试路径是迁移约束。

建议优先完成 M0–M3，再用 DLC 01 做首次扩展验收。矿石病 v2 可在 M2 建立健康端口后独立推进，不需要等待所有 DLC；正式合入时必须通过自己的平衡与边界检查。

**交付**

- 增加 `package.json`、锁文件、明确的 Node 支持范围及开发/校验命令。实施时选择兼容版本并锁定，不能依赖开发者机器上的全局库。

- 建立新旧实现的回放摘要对照，保留旧 VM 作为迁移期参照，验证记录不只含最终寿命，还包括事件/决策顺序和 RNG 游标。

**验收**

**回退**

**回退**

## 发布关卡与完成定义

目标 CI：安装锁定依赖 → 类型与依赖边界检查 → 内容校验 → 单元/契约/既有回归 → 固定场景及分布报告 → 生产构建 → 浏览器冒烟 → 部署。批量模拟和完整内容矩阵可按变更范围在 PR 或发行关卡执行；不能只运行构建。

“工程化完成”的判断应是：新增普通组织 DLC 不改模拟内核；新增健康模型只实现健康/风险契约；UI 更换不改变模拟结果；同一进程多个实例互不干扰；注册失败和事件失败不会留下半次修改；相同内容锁、规则版本与输入可复现。目录变多或 `.js` 改为 `.ts` 本身不构成完成。

## 本轮推进记录（2026-10-23 第四十二轮）：面试抽题迁到 TS —— 两处"抽签顺序"的细节

`interview.js` 里真正像规则的只有一段：一次面试从题库里抽几道题、抽哪几道。现在进
`src/model/interview-deck.ts`：

- `selectInterviewQuestions` —— 先组织级、后岗位级，各自洗牌后取 `draw` 指定的数量；
- **题库不足就整场取消**（不是"有几道问几道"）：玩家被告知无法安排面谈，原有工作不受影响；
- `shuffleDeck` —— 手写 Fisher–Yates，n 项恰好消耗 n−1 次随机值；
- `prepareSessionQuestions` —— 每道题的选项也洗牌，且选项数组与选项对象都**复制**一份，会话不会
  别名到题库（否则一次会话就可能改掉全局题库的顺序）。

两个容易忽视的点，都在测试里钉住了：

1. **洗牌用 `sort(() => rnd() - 0.5)` 是错的** —— 那个写法本身有偏，而且消耗多少次随机值取决于引擎
   实现。手写 Fisher–Yates 才能保证"n 项 = n−1 次"这个可断言的契约。
2. **`draw` 允许某个分组为 0** —— 那么该分组"候选为空"也是合法的（0 道题不缺）。这是唯一不触发
   "题库不足"的边界。

顺带删掉了 `interview.js` 里已经没人用的本地 `shuffle`，避免两份洗牌实现悄悄分叉。

证据：42 局兼容样本逐字节一致；`verify-interviews` 的 106 题 / 34 池 / 11016 种纸面组合全过；
1000 局分布 mean 52.919 / 任职 289 与上一轮相同；新增 `tests/interview-deck.test.mjs` 九条
（分组顺序、n−1 次抽取、题库不足、空池不抽签、`draw=0`、选项独立性、每题的抽取次数、一条走运行时的
会话构造断言）。

账本：legacy 文件仍 19（`interview.js` 227→**222** 行），typed 源码 39 → **40**，直写棘轮仍 312。

## 本轮推进记录（2026-10-23 第四十一轮）：重心加权迁到 TS —— 份额与"曲线不参与加法"的规则

`endYear` 的第一段把这一年的注意力分配成份额，再按份额施加各重心的效果表。规则只有两条，但两条都
容易被改坏，现在进 `src/model/focus.ts`：

1. **总权重为 0 时整年什么都不做** —— 没有份额、不施加效果，而不是"除以 0 得到 NaN 后再到处钳位"；
2. **`sm` / `arts` / `money` 不参与加法** —— 学识与技艺走边际递减曲线（`knowAdd`/`artsAdd` 要读当前
   上限），金钱不是四维。把它们也塞进加法会重复计算最"重"的那几个重心。

模型返回**增量**（`dimensions` / `knowledge` / `arts`），写入留给装配层 —— 因为学识与技艺必须走
`knowAdd`/`artsAdd`，而它们依赖当前上限，模型层拿不到也不该拿。

份额按调用方的键序保留，效果表也按自身键序输出 —— 这样"先钳哪一维"不取决于模型的迭代顺序，而是
取决于内容表，避免了一个只在极端值下才出现的顺序依赖。

证据：42 局兼容样本逐字节一致（重心份额进状态哈希）；四套渲染快照一致（`focusW` 被视图读取）；
1000 局分布 mean 52.919 / 任职 289 与上一轮相同；新增 `tests/focus.test.mjs` 十条（归一化、单一重心、
零权重、键序、效果拆分、零份额、两条走运行时的应用断言）。

账本：legacy 文件仍 19（`year.js` 455→**437** 行），typed 源码 38 → **39**，直写棘轮 314 → **312**
（`year.js` 的 `S.focusW` 2→0）。

## 本轮推进记录（2026-10-23 第四十轮）：家人职业与兄弟姐妹迁到 TS

`state.js` 里最后两块有"规则"味道的东西：家人的职业抽取与兄弟姐妹的构成。

- `npcJob` —— 24 次尝试：抽池 → 校验职业存在 → 校验国别/种族可用 → 校验性别限制 →
  **军队职业 82% 拒绝、艺术职业 70% 拒绝**；全失败退到 `vendor`，连它也禁用就 `seeking`；
- `ageJob` —— 七岁前幼儿、十六岁前在学、六十七岁后先掷 0.7 的退休骰，再抽职业；
- `siblingCount` / `siblingShape` / `siblingOutOfRange` —— 兄弟姐妹数量的权重（0:22 1:34 2:26 3:13 4:5）、
  每人三次抽取（性别 → 年长/年幼 → 1–7 年差），以及"以母亲生育年龄为锚"的范围检查。

**这一块的坑在抽取次数上**：军队/艺术分支各自要多掷一次降权骰，其余行业不掷。所以"每个候选消耗
1 次还是 2 次随机值"取决于职业的 `sec` —— 一旦把降权写成无条件掷骰，后面每一条人生都会漂移。测试
直接数调用次数：24 次尝试 × 2 次 = 48 次（全军事世界），性别受限时恰好 24 次。

顺带把 `npcJob` 里那段"给 NPC 抽职业"的注释删掉（它描述的是已经搬走的实现），并把父母职业也改成走
`TL.npcJobOf`，这样家人职业只有一个入口。

证据：42 局兼容样本逐字节一致（兄弟姐妹的名字与职业都进状态哈希）；四套渲染快照一致（家人面板直接
读这些字段）；1000 局分布 mean 52.919 / 任职 289 与上一轮相同；新增 `tests/family.test.mjs` 九条。

账本：legacy 文件仍 19（`state.js` 306→**266** 行），typed 源码 37 → **38**，直写棘轮仍 314。

## 本轮推进记录（2026-10-23 第三十九轮）：日志与四维变化迁到 TS —— 两个被所有模块调用的原语

`narrate` / `log` / `eff` 是三个最小的函数，却是**所有模块都经过的写入原语**。它们的语义原来只
体现在两个循环的形状里，现在进 `src/model/narrative.ts`：

- `logEntry` —— 每条记录都带 `age`/`year`/`text`/`kind`，`kind` 缺省为 `'ev'`，`extra` 覆盖式叠加；
- `logOverflows` / `logTrimStart` —— 日志上限 4000 条，超了就**一次性丢掉最旧的 500 条**
  （不是每写一条裁一次）；
- `applyEffectPatch` —— 四维按 `hl → h → so → sm → arts` 施加并钳 0–100，**金钱不钳位**
  （负债与横财都要能越界），且**假值不写**（`{hl: 0}` 等于什么都没发生）。

第三点看着琐碎，但它决定了"没有效果"与"效果为 0"是同一件事 —— 如果改成无条件相加，浮点值会在
无数次零效果之后被反复重新钳位，长期下来与原来不再逐字节相同。

**又一次同名冲突**：`applyEffects` 这个名字已经被 `src/model/effects.ts`（效果契约）占用，构建直接报
"The symbol already been declared"。这已经是本会话第三次同类事故（前两次是 `stageName`、
`subjectFromState`），于是按既定约定改成领域前缀 `applyEffectPatch`。

证据：42 局兼容样本逐字节一致；四套渲染快照一致（日志文本与 `kind` 都进快照）；1000 局分布

## 本轮推进记录（2026-10-23 第三十二轮）：生育概率迁到 TS，顺带被自己写错的端口咬了一口

`tryBirth` 的规则部分是"这对夫妻今年会不会再生一个"：国家没有 TFR 列，只能用城市化与教育水平反推
（`6.2 - urb/22 - edu/6`，钳 1–6）；没到目标子女数时权重 1、到了之后只保留 0.15 的间隔权重；
再加上母亲年龄窗口（16–46）与 27 岁峰值。这些进 `src/model/birth.ts`，孩子对象的构造、命名、
日志留在 legacy——形状和上一轮一致。

**两个保留的原作怪癖**（写进注释，不"顺手修"）：

1. 矿石病对生育力的 −45% 读的是**玩家自己**的分期，即使玩家是父亲——母亲的分期只影响母婴传播；
2. 母亲年龄窗口在玩家为男性时读的是配偶年龄，但男性玩家 > 60 岁会先被整个挡掉。

**这一轮真正踩到的坑**：装配层把国家对象直接当成端口返回（`nation: id => TL.NATION_BY_ID[id]`），
而模型按自己的词汇读 `urbanisation` / `education`，注册表里叫 `urb` / `edu`。于是 `undefined / 22`
得到 `NaN`，`Math.round(NaN)` 让"还要不要生"永远为假、概率恒为 `NaN`，掷骰恒失败 —— **整局人生一个
孩子都不会出生**。类型检查抓不到（装配层是 JS，端口值来自 `any`），渲染快照也抓不到（快照只看已渲染
的几个用例），是 **42 局兼容样本** 在第一个种子就报了哈希不符。

## 本轮推进记录（2026-10-22 第三十轮）：四维回归迁到 TS —— 这个游戏最核心的那条公式

`year.js` 的 ⑤⑥⑦ 三段是「四维不是加减而是每年向目标回归」：体质、羁绊、心境各自算一个目标值，

是两件事。这一轮搬进 `src/model/regression.ts`，拆成**目标 + 一步回归**两组函数：

- **体质**（速率 0.25）：年龄基准 + 饮食 1.5 + 运动 2 + 家境×1.5 − 吸烟 6 − 慢性病（未治 5 / 已治 2.5）
  − 难民 6 + 重心健康权重×6 − 负债 2 − 矿石病分期×7 − 未治肺结核 10；
- **羁绊**（非对称速率）：目标 45 + 伴侣 12 + 子女每名 4（封顶 15）+ 母亲 3 + 爱好 3 − 迁徙 6 − 公开感染 6，
  且**目标本身随年龄下滑 12 点**；
- **心境**（速率 0.20）：国家基线 + （体质−60）×0.16 + （羁绊−50）×0.18 + （收入分位−0.5）×22
  + 分期≥2 的 −12、公开感染的 −6 + 产出年份×0.1（封顶 6）。

写测试时先写错了一条假设：我以为羁绊是"成年后恢复更快、下跌永远慢"，实际上是**反的** ——

这才是"中年失去朋友很难补回来"的来源。代码没错，是我的注释和测试假设错了；注释已按实际语义改写，
测试也改成钉住这个不对称性（下跌 0.30 / 回涨 0.12，童年在两端都是 0.12）。

## 本轮推进记录（2026-10-21 第六轮）：题包内容锁与会话出处

**`contentLock.packages` 接上真实内容。** 新增 `src/content/pack-lock.ts`：题包身份 = `{id, version, hash}`，
`hash` 是对**规范化投影**做 FNV-1a 的校验和（纯算术，浏览器/Node 一致）。投影只取会改变
"问什么/怎么算分"的部分——题 ID、选项 ID、分数向量、题池装配、及格线；文案与声明顺序不参与，
所以改措辞不会让旧存档失效。装配层在存档时写入本局已注册的题包清单，读档时与内存清单逐条比对。

**失败即拒绝，并说清是哪一条。** 新诊断码：`content.package-missing` /
`content.package-version-changed` / `content.package-content-changed` / `envelope.package-duplicate`。
信封校验也会拒绝缺字段或重复的条目。

**面试会话自带出处。** 开始面谈时把 `{id, version}` 记进 `session.pack`（题目与选项本就是快照拷贝），
存档恢复后会话仍带着同一出处。测试证明：答完第一题 → 存档 → 新运行时恢复（保留答案与题面）→ 双方答完
得到的 `status` / `score` / `pool` 完全一致。

**顺手被这套检查抓到的一次真问题**：测试里我直接用 `answerOrganizationInterview` 推答案而没走
`TL.choose`，于是"待决抉择仍停留在上一题"，存档时信封如实记录，读档时按新题重算选项 → 立刻报
`pending.option-mismatch`。这正是恢复校验应有的行为（保存了一半的交互不会被悄悄替换成另一个问题）。

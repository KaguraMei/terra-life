# 组织 DLC 更新计划

2026-10-19。这里的 DLC 指分批交付的同人内容扩展包，不涉及付费或商店。本轮已完成面试与题库；下列组织深化和新组织尚未实施。

2026-10-20 工程化补充：后续加载器以[工程化架构决策](工程化架构决策-2026-10-20.md)为目标，先完成[实施路线](工程化实施路线-2026-10-20.md)中的注册与领域边界，再以 DLC 01 验证完整扩展。下文 `js/data/dlc/` 和 `files` 脚本清单是旧架构下的过渡草案；目标采用构建期内容清单、受控数据贡献和开局冻结注册表。内容发行顺序及设定约束继续有效，当前尚未实现完整加载器。

## 发行基线

核心版已有 18 组织、34 路线、36 条组织工作事件，以及历史去留、人物往来、离职履历。现在增加 106 道题、34 个面试池、结果解释和记录。黑钢国际、企鹅物流、喀兰贸易、雷神工业已经有基础路线，DLC 为它们增加深度，不重复创建同名组织。

卡西米尔当前有“感染者骑士团”路线及红松成员互动，但没有独立的红松骑士团职业组织。该基础与真正新增红松组织需要在迁移时区别处理。鲤氏侦探事务所、深海猎人也尚无独立可加入路线。

所有扩展复用[题库格式与接口](面试题库格式与DLC约束.md)。题库已有注册/追加和校验能力；完整组织 DLC 的清单加载、玩家开关、依赖解析与旧存档迁移尚待实现。当前可先按显式脚本顺序发行，不能把计划中的安装器写成现有功能。

非企业组织必须按身份选择加入形式，参考[整合运动与家族核查](整合运动与家族设定核查.md)。旧整合已在 1096 年结束可玩编制；九领导的新整合需独立设计维多利亚活动窗口、接触、分工和人物题库后再开放，不能恢复旧窗口或复用攻城时期的招募。家族相关扩展须区分新沃尔西尼禁令、其他城市活动以及具名家族的存亡。

## 建议发行顺序

| 包 | 类型与重点 | 职业闭环目标 | 面试和人物 | 历史/设定核对重点 |
| --- | --- | --- | --- | --- |
| DLC 01「合同与钢铁」 | 深化黑钢国际、雷神工业 | 黑钢安保/技术骨干 → 项目指挥或教官；雷神研发/测试 → 项目负责人；合同交接、装备验收、离职转制造业 | 增加合规与任务压力题；按在场年份交互芙兰卡、雷蛇；雷神优先普通工程人员，具名角色先核实雇佣关系 | 公司部门与地区活动窗；黑钢相关剧情、雷神实际供货关系；不得把所有使用雷神装备的人都写成雇员 |
| DLC 02「龙门夜行」 | 深化企鹅物流，新增鲤氏侦探事务所 | 物流接单 → 路线协调/护运负责人；事务所委托助理 → 外勤调查 → 独立案件承办；可结束委托、转物流或一般调查职业 | 物流增加多段交付题；事务所考察观察、委托边界、保密；核实后加入大帝、能天使、德克萨斯、老鲤、吽、阿、槐琥的限定互动 | 近卫局与私人组织权限不同；人物何时在龙门、何时离开；大型事件中的停业、路线封锁和委托变化 |
| DLC 03「雪线商路」 | 深化喀兰贸易 | 商贸/护卫 → 驻点协调 → 商路主管；开放新商路、雪线事故应对、地方协商，离职转一般贸易 | 增加本地需求与外部贸易取舍题；银灰、锏等互动需核定身份/时期，其他人物不自动视作员工 | 谢拉格政治变动与外贸开放时间；当地居民、喀兰员工、宗教机构三种关系分开 |
| DLC 04「红松之下」 | 新增独立红松骑士团，深化竞技生态 | 感染者竞技骑士 → 团内成员 → 赛事/护送骨干；竞技与互助双线，允许退赛、转护送或离团 | 团体面谈强调互助、职业生存、公共形象；核实后交互焰尾、灰毫、远牙、野鬃等成员 | 必须核实成立、起义、离开卡西米尔和行动去向；与原“感染者骑士团”路线迁移衔接，不假定所有感染骑士都属于红松 |
| DLC 05「深海回声」 | 新增深海猎人相关路线，单独处理特殊身份 | 先做调查/后勤协作与海岸救援；正式猎人身份是否开放须先完成设定和机制评估；保留退出协作/转救援路线 | 面谈可以筛选合作立场，不能靠答题把普通人变成深海猎人；具名互动拟覆盖歌蕾蒂娅、斯卡蒂、幽灵鲨、乌尔比安，但必须逐人核查窗口 | 特殊身体条件、来源和历史经历；海嗣相关风险、离海与任务节点；不用普通公司招募逻辑越过身份设定 |

上述人物是待核实的内容候选，不代表本轮已加入，也不代表官方确认每个人始终在这些组织内。角色中文名与身份以发行前实际条目核对为准。

## 每包的交付要求

建议每包新增至少 8 道组织题、每条受影响路线至少 2 道岗位题，减少重开时重复。题目数量不替代质量：每道题要有具体处境，至少两个有可解释取舍的选项；维度和阈值有设计依据。只加一道题即可验证框架，但不作为完整 DLC 的内容体量。

每个新增组织至少具备一条三阶段晋升路线、两条日常工作事件、一条多阶段特色事件链、一次历史变局或经营变化，以及明确的离职/转职出口。深化已有组织时，必须说明增加了哪些新体验，不能只换任务文案和工资数值。

具名人物初遇、再遇、关系变化需要相互关联的日志与冷却。基础框架当前只有有限次数的工作往来；复杂关系等级、跨组织人物联系和长任务链要作为该 DLC 的显式开发项，不能仅靠把名字填进联系人表宣称完成。

## DLC 文件与依赖约定

建议每个发行包使用 `dlc_<主题>` 稳定 ID，目录为 `js/data/dlc/<包id>/`，包含组织/路线补丁、事件链、题库对象及资料说明。面试题使用相同包前缀，题库扩展使用 `extensions`；不覆盖核心题 ID。

完整组织 DLC 清单拟使用以下字段，**此表是后续加载器契约草案，尚非运行时支持的 JSON**：

| 字段 | 计划约束 |
| --- | --- |
| `id` / `version` | 包 ID 与内容版本；版本升级附变更说明 |
| `requiresCore` | 明确所需核心格式/功能版本 |
| `dependsOn` | 其他内容包 ID 与最低版本；禁止环形依赖 |
| `files` | 只允许包目录内显式列出的相对脚本路径，不从外部 URL 动态执行代码 |
| `adds` / `extends` | 新增组织、路线和深化对象分开声明；现有公司不得重复建同名身份 |
| `sources` | PRTS 条目、核查日期、原剧情依据及游戏规则标记 |
| `migrations` | 旧 ID → 新 ID、旧履历/人物/面试结果的保留方式；缺迁移则不发布破坏性更新 |

在加载器完成前，通过 `index.html` 显式加载；涉及新组织时，需提供向 `ORGANIZATIONS` 和 `ORGANIZATION_LIST` 注册的代码，以及自己的事件注册，不能只追加题库。加载顺序为组织/路线定义 → 工作事件与历史节点 → 题库注册。已有组织基础事件不会自动替新 DLC 生成任务。

## 兼容与资料规则

现有组织 ID、岗位 ID、已记录的题目/答案 ID 不改名。若内容必须重构，提供映射，保留原履历展示。现有游戏只保存结果档案；未来支持中途存档时，再追加进行中面试/任务的格式版本和恢复策略。

当前“卡西米尔感染者骑士路线”不能无条件改成“红松成员”。迁移只在已有身份记录确证、年份与地区允许且玩家接受时发生，其他角色仍保留原路线。特殊组织的先决身份与面试成绩分别校验。

PRTS 核对以[组织总表](https://prts.wiki/w/泰拉大典:组织)为入口，再读取组织与角色具体条目、相关活动剧情。每个确切年份都需证据；不明年份使用明确标为项目规则的保守窗口。组织解散、停止招募、撤离某地不是同一件事；人物离任也不等于死亡。

本轮题库未进行新的完整 PRTS 逐角色考据。DLC 开发前的资料核对是必须完成的内容工作，尤其是深海猎人的特殊身份以及红松正式成立后的路线归属。

## 发布关卡

1. **资料与设计**：完成来源记录、身份门槛、年份窗、闭环路线和本包验收用例，先确定设定与游戏规则边界。
2. **数据与实现**：先加入题库/路线数据，再接任务、人物、历史变局和界面；不得从题目直接发职业或绕过资格复核。
3. **兼容验证**：重复 ID、错误引用、时间窗缺题、旧履历保留、进行中面试快照都需检查。
4. **玩法验证**：每条路线真实排程可招募；全部可抽试卷至少存在录用与不录用组合；特殊门槛不能靠高面试分绕过；离职、历史变局、人物失效年、自动模式均能结束。
5. **页面与模拟**：桌面和手机实际点击、长题滚动、结果解释、报告显示通过；运行固定种子样本，检查异常与分组织入职分布，再决定是否调概率和门槛。
6. **发行说明**：列出新增/深化范围、考据与二创部分、格式版本、已知限制和迁移措施，不把规划内容写成已上线功能。

现有证据：`tools/verify-interviews.mjs` 已验证核心 34 池和题库追加；`tools/verify-organizations.mjs` 已验证组织职业闭环；`tools/verify-organizations-ui.mjs` 已验证真实面试交互。下一步按 DLC 01 增加内容与针对性用例，不需要重写面试执行器。

# 矿石病系统重构提案（历史稿）

> 本文保留早期设计讨论。当前运行规则以[矿石病与源石技艺改进评估-2026-10-21](矿石病与源石技艺改进评估-2026-10-21.md)和代码为准；其中 `fusionPct = 100`、软临床评分、单一年度施术按钮等内容没有作为当前规则上线。

本文是设计提案，不直接改变当前运行代码。目标是把现有单一“结晶率”改成能表现感染者档案中常见的两类检测指标，同时保留游戏可读性和可平衡性。

## 这次读取到的资料

本地资料：[NGA 玩家整理页](C:/Users/Ayano/Downloads/整理了所有干员的感染程度，分享一点有趣的小发现 NGA玩家社区.html)。该帖整理了若干干员档案中的数值和描述，提出以下观察：

- 非感染者的体细胞与源石融合率记为 0，但血液源石结晶密度并不等于 0，整理中给出的常见值约为 `0.12u/L`。
- 轻度、中度、重度感染可以用血液源石结晶密度作大致分档：`<0.3u/L`、`0.3–<0.4u/L`、`>0.4u/L`。
- 体细胞融合率和血液浓度没有固定的一一对应关系。例如整理中列出的煌为 `16% / 0.24u/L`，赫拉格为 `13% / 0.21u/L`。
- 高融合率不一定意味着血液浓度同步升高；整理中把拉普兰德、阿米娅作为明显案例，并列出阿米娅 19% 的融合率。
- 档案描述、检测数值和临床表现可能出现不完全一致，白面鸮的例子被用来说明血液浓度不能单独决定“轻度/重度”标签。

PRTS 的[《大地巡旅》总页](https://prts.wiki/w/大地巡旅)目录明确列出“Chapter 1.4 矿石病（第 25–31 页）”，但对应的 [Chapter 1.4 子页面](https://prts.wiki/w/大地巡旅/Chapter_1.4_矿石病)目前显示为空页；[“矿石病”页面](https://prts.wiki/w/矿石病)也没有可用正文。因此，本提案只把《大地巡旅》作为设定来源入口，把 NGA 数值作为角色档案案例，不把这些阈值宣称成完整医学定律。

## 为什么要从单一结晶率改成双指标

现有 `S.ori.crystal` 同时承担感染程度、体表结晶、器官恶化、死亡风险和治疗效果，导致几个问题：

1. 一个数值无法表达“体表结晶明显，但血液浓度仍可控”这类案例。
2. 治疗只能整体减速，不能区分短期控制血液浓度和长期逆转体细胞融合。
3. 数值达到 100 后只能硬判死亡，无法表达临床上“已经很严重，但仍可能维持一段时间”的状态。
4. 事件条件只能写“结晶率高低”，不能分别触发检测、隐瞒、工作限制、器官症状和医疗决策。

## 建议的状态模型

将 `S.ori` 改为版本化对象，保留 `crystal` 作为旧存档兼容字段一段时间：

```js
S.ori = {
  version: 2,
  at: 34,
  detected: true,
  fusionPct: 13.0,          // 体细胞与源石融合率，0–100%
  bloodDensity: 0.21,       // 血液源石结晶密度，u/L
  bloodTrend: 0.004,        // 近期变化，不是永久增长率
  organLoad: {               // 隐藏的临床负担，决定症状与终末风险
    skin: 0.32,
    limb: 0.18,
    lung: 0.08,
    nerve: 0.04,
    core: 0.02
  },
  symptoms: { pain: 0.1, fatigue: 0.2, fever: 0.0 },
  stage: 1,
  clinicalBand: 'mild',
  treated: false,
  provider: null,
  regimen: null,
  adherence: 0.8,
  resistance: 0.0,
  congenital: false,
  confidence: 'clinical',
  history: []
};
```

`fusionPct` 表示组织结构已经被改变的程度，变化慢、很难逆转；`bloodDensity` 表示循环中的源石结晶负担，变化快，可以被治疗、暴露和身体状态拉动。`organLoad` 不直接向玩家显示精确数字，只用于把同样的两个检测值转化为不同症状。这样可以出现“检测值相近但症状不同”，也能避免把某个干员案例硬套成全民规则。

## 临床分级不要只看一个阈值

建议保留血液浓度的三个易懂标签，但用软阈值和临床修正计算最终状态：

```text
bloodBand = <0.30 mild, 0.30–0.40 moderate, >0.40 severe
clinicalScore =
    0.35 * normalized(bloodDensity)
  + 0.25 * normalized(fusionPct)
  + 0.30 * organLoad.coreAndLung
  + 0.10 * symptomBurden
```

最终的 `clinicalBand` 由 `clinicalScore`、近期趋势和医生诊断共同决定。这样可以保留档案里的例外：血液数值看似中度，临床描述仍可能是轻度；高融合率可以显著增加体表结晶和技能代价，却不自动等同于高血液浓度。

建议使用五档临床状态：

| 状态 | 主要含义 | 游戏表现 |
| --- | --- | --- |
| 潜伏 | 已有异常但尚未确诊 | 暴露后体检、隐瞒和误诊事件 |
| 轻度 | 可工作，症状有限 | 少量体质/心境影响，治疗选择增加 |
| 中度 | 需要持续管理 | 工作限制、复诊、药物成本和社交风险上升 |
| 重度 | 器官负担明显 | 体质下降、行动风险、组织安置或排斥 |
| 终末 | 器官负担持续失代偿 | 死亡风险快速上升，但不把单次读数直接等同于立即死亡 |

“终末”应由器官负担、趋势和症状触发。`fusionPct = 100` 可以作为终末候选条件，但不能再像旧 `crystal = 100` 那样单独硬判；如果要保留 100% 的明确边界，应该把它定义为“结构性不可逆终末状态”，并允许最终死亡在同年或后续少数年份发生。

## 感染、恶化和治疗应拆成三条链

**感染链**负责“是否感染”：接触源石粉尘、天灾清理、矿业、源石技艺、伤口暴露等改变感染概率。它不直接把数值推到高融合率。

**病程链**负责“感染后如何变化”：

- 血液浓度按月度或年度小幅波动；急性暴露可以造成短期尖峰。
- 体细胞融合率按较慢速度增加；健康、种族、既有融合部位和治疗历史改变斜率。
- 器官负担从两个指标和个体差异中派生，并有少量不可预测性。
- 大事件、贫困和工作环境主要改变趋势与复发概率，而不是每次直接增加固定百分比。

**治疗链**负责“能否控制”：

- 抑制治疗优先降低血液浓度和近期趋势，不能自动清除既有融合。
- 罗德岛、阿撒兹勒等医疗来源可以使用不同的“控制效率、费用、风险和可及性”参数。
- 断药、药物短缺和高强度工作会使血液浓度反弹；反弹幅度不应直接抹掉历史融合。
- 研究性治疗可以降低器官负担或提高控制上限，但带有失败、排斥和资料不足的风险，不直接写成稳定治愈。

## 对当前代码的替换边界

建议把现有函数迁移为以下接口，先保留旧函数名作为适配层：

```js
TL.oriInfect(S, exposure)
TL.oriAdvance(S, dt)
TL.oriClinicalBand(S)
TL.oriSymptoms(S)
TL.oriTreatmentOptions(S)
TL.oriMortalityHazard(S, age)
TL.oriReport(S)
```

`oriYear` 不再直接累加单个 `crystal`；`causeWeights` 使用 `organLoad` 和 `clinicalBand`；`oriStigma` 使用“是否确诊、临床状态和地区容忍度”；`combatValue` 只读取症状与技能适应，不把血液浓度简单当作战斗力加成。

UI 建议同时显示三项：

```text
体细胞融合率 13%       ↑ 缓慢增加
血液源石结晶密度 0.21u/L  → 可控
临床状态：轻度感染       已确诊 / 抑制治疗中
```

普通玩家看到标签和趋势，报告页再显示精确值；这样既保留设定感，也不会让玩家误以为 0.31 和 0.32 是绝对不同的医学边界。

## 事件和玩法机会

- **初检**：角色可以选择公开、隐瞒、复检或接受更昂贵的检测；检测误差和地区医疗水平影响结果可信度。
- **工作**：矿工、天灾信使、前线术师更容易出现血液浓度尖峰；稳定组织可以调整岗位，临时合同可能终止合作。
- **治疗**：短期抑制、长期方案、实验治疗和黑市药物各有代价，不再只有“治疗/不治疗”二选一。
- **关系**：亲友可能只看到体表结晶；医疗人员关注血液浓度；组织管理者关注器官负担和行动风险，三者会产生不同反应。
- **特殊案例**：高融合低血液、高血液低融合、治疗后浓度下降但融合继续增加，都可以由同一套模型自然生成。

## 迁移与验证

当前项目没有中途人生云存档，所以新开人生可以直接使用 v2；旧浏览器摘要只需在报告渲染层继续读取旧 `ori.crystal`。如未来支持中途存档，迁移器应标记 `confidence: 'legacy-estimated'`，避免伪装成真实检测值。

第一轮实现应先建立 6 个不变量测试：

1. 非感染者的 `fusionPct` 为 0，但血液检测可以有背景值。
2. 血液浓度和融合率可以在合理范围内独立变化。
3. 抑制治疗降低血液浓度趋势，却不直接清零融合率。
4. 高融合率不会自动触发高血液浓度，反之亦然。
5. 终末死亡由器官负担与趋势触发，并记录矿石病死因。
6. 旧存档的 `crystal` 可以读出，但不会被误称为 v2 的任一单项检测值。

这套拆分能利用 NGA 整理中最有价值的发现：感染不是一个从 0 到 100 的单轴进度条，而是组织融合、血液负担、器官损伤和社会处境共同构成的病程。

## 建议在实现时再加的五个约束

### 1. 把“暴露”与“感染”分开

新增一个不等于感染的 `exposureDose`。矿区工作、天灾清理、源石粉尘伤口和长期居住环境先累积暴露剂量，达到个体阈值后才有感染判定。短时高剂量可以造成血液密度尖峰，但不应直接把体细胞融合率推到中后期。这样能表现“做过高危工作但没有感染”和“离开高危工作后仍在发病”两类情况。

### 2. 检测值要有背景值、误差和可信度

非感染者的血液检测不必为零，建议在 `0.08–0.15u/L` 附近生成背景值；单次接近 `0.12u/L` 不能直接诊断。每次检测记录 `measuredRange`、`labQuality` 和 `confidence`，复检、医疗条件和设备差异会影响报告。游戏显示可以写成“约 0.21u/L”，内部再保存精确值，避免把小数点后的差异变成绝对规则。

### 3. 分期需要滞后和恢复条件

临床分期由评分计算，但升级应连续两次检查超过门槛才确认；降级则要求更长时间的稳定控制。这样治疗后血液密度下降不会让角色在轻度、中度之间每年反复横跳，也不会因为一次急性暴露就突然进入终末状态。`stage` 是临床标签，不能反向覆盖两个原始检测值。

### 4. 源石技艺只改变暴露和症状，不直接决定病程

当前代码把技艺等级直接乘到年度病情增长上，容易生成“会用源石技艺就必然恶化”的单一结论。建议改为个体的 `sourceAffinity`、职业暴露、伤口情况和治疗历史共同决定病程；技艺可以增加某些症状或急性尖峰，但不应单独决定融合率增长。种族参数也应作为先验修正，而不是绝对豁免或绝对易感。

### 5. 用器官画像替代一个万能终末值

不同个体的终末路径可以不同：肺部负担影响呼吸和感染并发症，神经负担影响行动与源石技艺控制，皮肤和肢体负担影响体表结晶与工作能力，核心负担才主要进入矿石病死亡风险。`organLoad` 可以由融合部位、暴露类型和治疗反应共同更新；这样同样的融合率不会得到完全相同的人生结果。

## 推荐的实现顺序

1. 先增加 `version: 2` 数据结构、迁移器和只读兼容字段，保证所有旧事件还能用 `stage / treated / known`。
2. 再实现 `exposureDose`、双指标推进和 `clinicalBand`，把 `oriYear` 改成只负责调用新模型。
3. 接着迁移死亡率、治疗费用、工作限制和 UI；旧 `crystal` 只在历史摘要中显示为“旧版结晶率”。
4. 最后逐个改事件条件和特殊人物文本，并用高融合低血液、高血液低融合、治疗后反弹三组固定样例做回归测试。

这套顺序能先稳定医学模型，再调整叙事和数值平衡；如果直接替换所有 `crystal` 条件，旧事件会在同一轮迁移中失去语义，调试成本会很高。

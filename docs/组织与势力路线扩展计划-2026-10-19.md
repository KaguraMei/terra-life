# 组织与势力路线扩展计划

日期：2026-10-19
状态：组织路线与多轮面试已实现；后续组织深化按[组织 DLC 更新计划](组织DLC更新计划.md)推进。实际范围、设定边界与接口见[组织系统实现与面试接口](组织系统实现与面试接口.md)。下文保留原计划用于对照。

## 目标

在现有泰拉人生模拟中加入可被认识、申请、加入、晋升、退出和转职的组织路线，并让组织路线受到国家、种族、职业、年龄、年份、感染状态和大事件影响。

本轮优先覆盖用户指定的路线：

- 莱茵生命；
- 梅兰德基金会；
- 萨卡兹 / 卡兹戴尔的佣兵与军事组织；
- 拉特兰教宗铳骑、拉特兰戍卫部队；
- 卡西米尔竞技骑士与感染者骑士团；
- 龙门近卫局；
- 炎国司岁台与秉烛人；
- 叙拉古家族与新沃尔西尼市政路线。

后续可以沿用同一框架扩展黑钢国际、企鹅物流、喀兰贸易、雷神工业、鲤氏侦探事务所、深海猎人、红松骑士团等组织。

## 已确认的项目结构

当前项目已经有一部分可复用基础：

- `js/data/timeline.js` 有 `TL.ORGANIZATION_ERAS`、`organizationAvailable()` 和 `contentAvailable()`，目前只登记了罗德岛与整合运动；
- `js/data/jobs.js` 使用扁平职业表，支持国家限制、学历、技艺、风险、收入、干员分支和通用干员阶级；
- `js/data/events.js` 使用事件池、冷却、次数上限、组织门槛和 `TL.SUPPLEMENTAL_EVENTS`；
- `js/data/decisions.js` 已经有罗德岛和整合运动的加入抉择；
- `js/data/timeline.js` 能在特定年份施加全国效果、记录旗标、触发个人后果和直接死亡；
- `js/engine/year.js` 已经把年度事件、年表事件和抉择串成闭环；
- `TL.JOBS` 里已有 `mercenary`、`bounty`、`guard`、`police`、`soldier`、`knight`、`engineer`、`doctor`、`scholar` 等可作为新组织路线入口的职业。

因此不需要重写年度循环，主要工作是增加组织状态层、组织数据层和组织专属调度。

## PRTS.wiki 调研结论

本次先读取了 PRTS 的组织总表和几个具体条目。`/w/势力` 页面目前为空，实际可用入口是“泰拉大典：组织一览”和“泰拉大典：组织/其他”等页面。

### 莱茵生命

来源：[泰拉大典：莱茵生命](https://prts.wiki/w/泰拉大典:组织/莱茵生命)

- 1083 年由克丽斯腾与塞雷娅联合创立实验室；
- 1085 年获得包括梅兰德基金会在内的投资，转为莱茵生命有限公司；
- 1090 年建立科室制度；
- 1092 年工程科、商务科、科学考察科建立；
- 1095 年炎魔事件后塞雷娅离开；
- 1097 年参与“地平弧光”计划；
- 1099 年发生 359 号基地事件和特里蒙弧光事件；
- 组织内部有构件、能量、结构、源石技艺应用、生态、科学考察、工程、防卫、商务、人力资源等方向。

这条路线适合做成“科研 / 工程 / 防卫 / 科考 / 商务”多分支职业，而不是单一的莱茵生命职业。

### 梅兰德基金会

来源：[泰拉大典：组织/其他](https://prts.wiki/w/泰拉大典:组织/其他#梅兰德基金会)，以及莱茵生命条目中的投资记录。

- PRTS 记录的核心成员是创始人梅兰德·塞勒涅；
- 莱茵生命条目明确记录基金会参与其商业化投资；
- 目前资料更适合支持“基金、调查、救援、技术和政治项目”的身份路线，不宜直接假设为普通公司式招工。

因此第一版建议把它做成“受资助者 / 项目调查员 / 基金会联络人”，并允许与莱茵生命形成合作或冲突，而不是强行做成固定岗位。

### 龙门近卫局

来源：[泰拉大典：龙门近卫局](https://prts.wiki/w/泰拉大典:组织/龙门近卫局)

- 近卫局是龙门警备力量和安全部门的结合体；
- 有稳定的选拔考核和等级制度；
- 特别督察组是高风险岗位，成员通常任期较短；
- PRTS 条目列出陈、星熊、诗怀雅等关键人物；
- 1096 年末龙门与罗德岛开始合作，陈负责对接；
- 后续龙门事件会导致陈离开近卫局，诗怀雅进入接班路线。

这条路线非常适合做“警员 → 特别督察组 → 高级警司 / 退职 / 罗德岛合作”的闭环。

### 炎国司岁台与秉烛人

来源：[泰拉大典：炎](https://prts.wiki/w/泰拉大典:地理/炎)

- 司岁台是炎国为应对岁兽问题设立的官方机构；
- 在此任职者统一称为“秉烛人”；
- 主要职责是跟踪和监视岁兽代理人的行动；
- PRTS 列出左乐为司岁台秉烛人，并记录其与罗德岛的联系。

该路线应当是“高门槛、低概率、官方身份明显”的特殊路线。当前资料没有提供完整的公开晋升表，因此第一版只实现“候补 / 秉烛人 / 外勤任务”三段，并把更细的官阶标成项目设定。

### 卡西米尔竞技骑士

来源：[泰拉大典：组织一览](https://prts.wiki/w/泰拉大典:组织)和项目已有卡西米尔年表。

- PRTS 将卡西米尔商业联合会、卡西米尔骑士协会、国民警察、多个竞技骑士团、红松骑士团列为独立组织；
- 项目已有竞技骑士 `knight` 职业；
- 项目年表已有 1050 年商业联合会建立、1094 年耀骑士流放、1097 年感染者起义。

因此现有 `knight` 可以保留为经济职业，新增组织归属和赛事晋升：签约骑士、赞助骑士、正式骑士、冠军或地下骑士团成员。

### 萨卡兹 / 卡兹戴尔

来源：[泰拉大典：组织一览](https://prts.wiki/w/泰拉大典:组织)和项目已有卡兹戴尔年表。

- PRTS 列出卡兹戴尔军事委员会、伦蒂尼姆萨卡兹王庭军等军事组织；
- 项目年表已有 1086 年巴别塔成立和 1094 年斩首行动；
- 佣兵作为职业已经存在，但目前没有“萨卡兹佣兵组织归属、合同等级和大事件退出”状态。

这条路线的可行做法是保留通用佣兵职业，新增“佣兵合同 / 卡兹戴尔军事委员会 / 王庭军外勤”归属。萨卡兹种族或卡兹戴尔出生会提高认识和招募概率，但不能直接保证加入。

### 拉特兰铳骑与部队

来源：[泰拉大典：组织一览](https://prts.wiki/w/泰拉大典:组织)

组织表中列出了拉特兰教宗铳骑、金律法卫、拉特兰戍卫队、拉特兰中庭公证所等机构。具体招募条件并不完整，因此计划采用“拉特兰公民 / 萨科塔身份优先，异族或外来者走公证所、戍卫协作或外派路线”的保守实现。

### 叙拉古家族与市政路线

来源：[泰拉大典：叙拉古](https://prts.wiki/w/泰拉大典:地理/叙拉古)和项目已有 `sir_families`、`sir_newcourt` 年表事件。

- 叙拉古由十二家族和灰厅处理重大事务；
- 新沃尔西尼建立后，旧家族法典被废除，市政和独立司法路线出现；
- PRTS 记录新沃尔西尼市长候选和家族成员转入新政体的关系。

实现规则应明确：

1. 1099 年前可以申请或被家族吸收；
2. 1099 年后旧家族关闭“新招募”入口；
3. 已加入者触发“留在家族、退出、转入市政 / 司法、流亡”抉择；
4. 市长或市政路线只能在新法庭 / 新沃尔西尼状态出现后开放；
5. 家族人物互动和市长人物互动使用不同联系池，不能混成普通叙事。

## 建议的数据模型

### 1. 组织注册表

新增 `js/data/organizations.js`：

```js
TL.ORGANIZATIONS = {
  rhine: {
    name: '莱茵生命', kind: 'company', nation: 'CLB',
    from: 1085, stateByTimeline: true,
    routes: ['research', 'engineering', 'defense', 'fieldwork', 'business'],
    contacts: ['kristen', 'saria', 'pavlis', 'muir', 'yara', 'doro']
  }
};
```

每个组织只保存“组织事实和机制入口”，具体叙事仍放在事件和抉择文件中。

### 2. 人生状态

在 `S` 中增加：

```js
affiliation: null,
orgHistory: [],
orgContacts: {},
orgRoute: null,
orgRank: 0
```

`S.job` 继续表示谋生职业，`S.affiliation` 表示组织归属。这样“工程师 + 莱茵生命”“警员 + 龙门近卫局”“学者 + 梅兰德基金会”可以同时成立。

为兼容旧存档，也可把关键状态同步写入 `S.flags.org_*`，但新代码不再只依赖散落旗标。

### 3. 组织状态机

新增几个统一接口：

- `TL.organizationState(S, id)`：返回未成立、开放、限制、解体、改组等状态；
- `TL.canJoinOrganization(S, id, route)`：检查时间、国家、种族、职业、年龄、教育、感染状态和历史事件；
- `TL.joinOrganization(S, id, route)`：写入归属、职业转换和加入年份；
- `TL.leaveOrganization(S, reason)`：记录退出原因，必要时转入新路线；
- `TL.promoteOrganization(S)`：根据组织路线和累计服务年限推进等级；
- `TL.organizationContact(S, id)`：按概率触发人物互动并写入冷却和已认识记录。

### 4. 组织事件结构

组织事件继续使用现有 `EVMAP`，增加约定字段：

```js
{
  organization: 'lungmen_guard',
  route: ['guard', 'police'],
  contact: 'chen',
  fromYear: 1096,
  state: ['active'],
  max: 1,
  cd: 8,
  when: S => ...,
  run(S) { ... }
}
```

事件调度分三类：

- 招募事件：认识组织、投递、考核、被拒或等待；
- 服役事件：任务、培训、部门调动、人物互动、晋升；
- 转折事件：大事件导致停招、解体、改组、退职或转职。

人物互动不是固定必遇，而是组织归属、路线、年份和事件状态满足后按低概率抽取。例如罗德岛—博士、近卫局—陈 / 星熊 / 诗怀雅、秉烛人—左乐、莱茵生命—科室主任。

## 实施阶段

### 阶段 0：资料登记与规则边界

- 建立组织来源表，逐条记录 PRTS URL、组织类型、成员、已知年份和可信度；
- 将“官方资料”“PRTS 条目事实”“项目推断”分开；
- 对没有明确成立年或招募条件的组织，不伪造官方年份，使用 `confidence: 'inferred'` 或 `project-rule`。

### 阶段 1：组织状态框架

- 新增 `js/data/organizations.js`；
- 扩展 `TL.organizationAvailable()`，支持成立、解体、改组、停招、仅存量成员等状态；
- 在 `state.js` 增加归属、履历、路线和人物联系状态；
- 保持罗德岛 / 整合运动旧逻辑兼容。

### 阶段 2：职业与晋升闭环

- 将组织路线绑定到现有职业，而不是复制一套独立收入模型；
- 新增组织专属职业或路线字段，例如 `org`, `route`, `rankTable`, `exitTo`；
- 把通用 `job_promote` 改为：无组织时走通用提拔，有组织时优先走组织晋升；
- 明确每条路线的失败、退出、转职和失业回退。

### 阶段 3：招募、服役和人物事件

- 每条 P0 路线至少提供：一次认识 / 招募、一次加入结果、一次失败或拒绝、两次服役事件、一次晋升事件、一次人物互动；
- 人物事件设置低概率、冷却和一生次数上限；
- 组织事件加入 `SUPPLEMENTAL_EVENTS`，不直接增加每年事件数量；
- 组织成员有稳定的年度机会，非成员只能在特定地点、职业或大事件下偶遇。

### 阶段 4：大事件闭环

- 莱茵生命：把 1095、1097、1099 年表事件接入组织状态和部门去留；
- 龙门近卫局：增加 1096 合作窗口，并在切城事件后处理陈离职和诗怀雅接班；
- 叙拉古：在 1099 年把旧家族标为“停止新招募”，为存量成员排入转型抉择；
- 卡西米尔：让感染、流放、红松路线与现有年表旗标互相影响；
- 卡兹戴尔：让巴别塔和斩首行动改变佣兵合同与阵营选择；
- 炎国：让司岁台路线受岁兽相关年表和人物接触影响；
- 拉特兰：让 1099 万国峰会改变异族、感染者和外派路线的开放程度。

### 阶段 5：界面与报告

- 当前职业旁增加“组织 / 路线 / 等级”；
- 人生报告增加组织履历、晋升记录、主要人物联系和退出原因；
- 组织已解体时显示“曾任 / 已退出”，不显示为当前工作；
- 继续保留当前死亡来源、职业和年度风险展示。

### 阶段 6：验证

新增 `tools/verify-organizations.mjs`，至少验证：

- 每条组织路线能从真实 `scheduleEvents()` 进入并执行；
- 晋升不会跳级、不会重复、不会在失业后继续计薪；
- 叙拉古 1099 年后新角色不能加入旧家族；存量成员能进入转型抉择；
- 近卫局、莱茵生命、司岁台的错误国家 / 年份 / 路线不会误触发；
- 人物互动有冷却和次数上限；
- 组织事件不会绕过 `TL.fire()`，不会重复施加大事件效果；
- 1000 局自然模拟仍能结束，且不会产生未定义职业、组织或报告字段。

## 可行性结论

整体可行性高，原因是现有项目已经具备事件池、年表、职业门槛、组织年份门槛和自动验证脚手架。最大的工作不是年度循环，而是建立统一的组织状态和路线转移模型。

风险主要有四项：

1. **把组织当职业**：会导致一个人无法同时拥有“职业”和“组织”，也会破坏收入与死亡风险模型；
2. **只写招募事件**：加入后没有年度服役、晋升、退出和人物互动，路线会变成一次性彩蛋；
3. **忽略历史转折**：叙拉古旧家族、巴别塔、莱茵生命防卫科等在大事件后状态不同，必须支持“停止新招募”和“存量成员迁移”；
4. **把项目推断写成官方事实**：PRTS 组织总表能证明组织存在，但不一定能证明招募条件、官阶或成立年份。所有概率、等级和细节应标注为项目规则。

建议按 P0 八条路线先做一套完整闭环，再把 PRTS 组织一览中的其他公司和军事组织批量接入。这样可以先验证框架是否稳定，再扩充内容量。

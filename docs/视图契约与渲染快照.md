# 视图契约与渲染快照

原计划第 4 项要求"渲染器只读派生视图"。这件事的风险全在**看不见**：渲染是字符串拼接，
改完没有编译错误，只会悄悄少一个标签、错一位数字。所以先补网，再动代码。

## 边界：什么属于视图，什么属于 UI

`deriveLifeView(state)` 只放**关于这个人**的事实，且都是原始值（id、数字、字符串），不带任何
本地化标签：

| 视图分区 | 内容 |
| --- | --- |
| `identity` | 姓名/简称、国家、种族、性别、出生年、当前年龄、城市、王庭（id 与名）、阶层与阶层码、家境分位、学历、是否流亡、是否仍住父母家、源石技艺值与等级、寿命区间 |
| `attributes` | 四维原始值（健康/心境/学识/羁绊），不取整 |
| `mortality` | 是否已结束、死亡年龄、死因 id、上一年度死亡风险 |
| `health` | 是否感染、分期、结晶率、感染年龄、是否接受治疗、身份是否公开 |
| `survival` | 预期寿命、当前年龄的同期群存活比例、整条同期群曲线 |
| `schooling` / `service` | 在校学校与剩余年限、服役剩余年限 |
| `family` | 母亲/父亲/配偶，以及兄弟姐妹与子女的列表（姓名、年龄、职业 id、是否在世） |
| `peers` | 同期群规模与每个成员的姓名与死亡年龄 |
| `scene` | 像素场景的确定性种子与是否处于天灾余波 |
| `focus` | 本年可选的焦点、已练习权重、所属人生阶段 id（字符串，内容层定义） |
| `feed` | 人生日志的只读投影：种类、年龄、文本、可选标签 |
| `career` | 当前职业、最高职业、是否退休、组织与路线与等级、干员职业与等级、组织履历（含入职年与闭合状态） |
| `economy` | 月收入、现金、净资产、负债、收入分位、口粮折算、是否有退休金、退休金月额 |
| `annual` | 逐年一行：年龄、职业、收入、分期、结晶率、**心境**（人生地图按它上色） |
| `calendar` | 当前年份 |

明确**不进视图**的三类：

1. **节奏与播放状态**：`t`、`yearSec`、`paused`、`speed` —— 这是播放器的事，不是人物事实。
2. **哪一屏在显示**：`S.report`（报告页是否打开）、`pending`（是否有待决抉择）—— 属于 UI 状态机。
3. **本地化文本**：视图给 `stratum`、`eduLevel`、`job` 这类 id，`TL.nameOf` / `TL.eduName` / `TL.jobLabel`
   留在渲染器里。视图不读语言，因此同一份视图能被任何语言的界面渲染。

内容侧自己的推导（源石技艺等级 `TL.artRank`、净资产 `TL.netWorth`、同期群存活 `TL.cohortAliveAt`）
通过**适配器**注入，模型层不 import 内容规则：

```js
runtime.deriveLifeView = state => deriveLifeView(state, {
  artsRank: life => runtime.artRank(life),
  netWorth: life => runtime.netWorth(life),
  cohortAliveAt: (life, age) => runtime.cohortAliveAt(life, age)
});
```

取整与分段文案（`Math.round`、`TL.statWord` 的"硬朗/平淡"）留在渲染器：视图给原始数值，
显示策略属于界面。

## 渲染快照网

`tools/ui-render-harness.mjs` 在一份假 DOM 上加载**真实**的 `js/ui/render.js`（画布用空实现的
2D 代理，只保证调用不炸），渲染一个准备好的状态，然后回读指定元素的 `innerHTML` / `textContent`。

`tests/render-snapshots.test.mjs` 用四个固定用例冻结「顶栏 + 身份 + 状态 + 财产 + 生存 + 家庭 + 同龄人 + 人生地图 + 场景 + 焦点 + 日志 + 弹层」共 **41 个元素**的产物：

| 用例 | 覆盖的分支 |
| --- | --- |
| `birth` | 婴儿、未就学、无组织；`focus` 为空 |
| `worker` | 26 岁在职，94 条日志 |
| `infected-operator` | 34 岁、感染标签、干员等级、组织路线与等级；144 条日志 |
| `retiree` | 70 岁退休、父母双亡、三子女；215 条日志 |

**用例必须自己证明活着。** 早期版本按目标年龄命名，但种子在 9 岁就死了，于是"26 岁工人"其实渲染的是
一个 9 岁的尸体——快照照样通过，覆盖却是假的。现在 `lifeAt()` 断言 `phase === 'life'` 且
`age >= 目标年龄`，选种子时先扫过一遍，`joinOrganization` 失败也会直接报错。

替身 DOM 也升级过一次：`renderFeed` 是**增量建 DOM**（`createDocumentFragment` + `insertBefore` +
`querySelector('.txt')`），只存 `innerHTML` 字符串的话根本查不到子节点。现在这个迷你 DOM 会把
`innerHTML` 解析成子树、支持片段与 `querySelector`，序列化结果稳定，日志与弹层才真正被冻住。

改渲染前先在旧代码上生成基线，改完比对；重新生成要先读 diff，因为**快照变化就是玩家看到的变化**：

```bash
node --test tests/render-snapshots.test.mjs                     # 比对
RENDER_SNAPSHOT_WRITE=1 node --test tests/render-snapshots.test.mjs   # 重新生成（需解释 diff）
```

## 报告页快照

报告屏由 `main.js` 自己渲染（它是一个"屏幕"，不是面板），所以 `tests/report-snapshot.test.mjs`
直接 **boot 真实应用**，用文档里已有的 `?go=1&auto=1&seed=…&by=…&ff=…` 路径跑完一局：

- 种子由 URL 字符串哈希得到，`auto=1` 让所有抉择自动选，`ff=N` 快进到指定年龄；
- 死亡后 `finishLife` 渲染报告并切屏，测试断言 `phase === 'report'` 且 `#report` 可见；
- 冻结 `rTitle` / `rDead` / `rGrid` / `rChartLbl` / `rWealthLbl` / `rLogLbl` / `reportLog`
  （两张图是 canvas，不在标记里）。

三个用例覆盖不同形态：

| 用例 | 种子 | 形态 |
| --- | --- | --- |
| `long-life` | `rep-5` | 92 岁、3 名子女、12 个格子 |
| `organization` | `life-16` | 30 岁、`raythean` 1 级、16 个格子（多出组织与路线两行） |
| `infected` | `life-4` | 18 岁、感染 Ⅱ 期、15 个格子 |

用例自带漂移断言：种子若换了年龄、组织或感染状态，测试会直接说"age drifted / organization drifted"，
而不是给出一份看起来正常、其实换了人的报告。重新生成：

```bash
REPORT_SNAPSHOT_WRITE=1 node --test tests/report-snapshot.test.mjs
```

## 开局页快照

出生屏（掷签 + 出生证明）由 `js/ui/landing.js` 渲染，掷签动画走 `setTimeout`。替身 DOM 因此带了一个
**可排空的定时器队列**（`runTimers()`），测试不必等真实时间；`specified: true` 走单帧路径。

`tests/landing-snapshot.test.mjs` 冻结三个用例：指定国家、随机抽取（26 帧掷签后落到目标）、按人口模式，
覆盖 13 个元素（标题、抽签表、掷签结果、证书编号/姓名/正文/字段/概览/同龄人）。用例带漂移断言：
抽取到的国家或种族变了就报 `drawn nation drifted`，而不是换一份证书照常通过。

```bash
LANDING_SNAPSHOT_WRITE=1 node --test tests/landing-snapshot.test.mjs
```

| 批次 | 状态 | 说明 |

| 顶栏 + 身份记录 | ✅ 完成 | 姓名、阶层、城市、王庭、感染标签、干员/组织标签、属性表、MRZ 机读区、像素头像签名全部改读视图；四个用例快照逐字节不变 |
| 状态（四维 / 财产 / 生存） | ✅ 完成 | 四维原始值、技艺等级、结晶率、净资产、年收入、负债、收入分位、年度风险、同期群曲线与预期寿命全部改读视图；改前改后除新增的 `survStat` 键外逐字节一致 |
| 家庭与关系 | ✅ 完成 | 亲属名单与同期群成员改读视图（`family` / `peers`），测试覆盖 2/3/8/3 条亲属与 6 位同龄人、`peerSum` 百分比与 58–78 格人生地图；改前改后逐字节一致 |
| 履历与场景 | ✅ 完成 | 场景签名与说明、焦点选项与阶段、日志、抉择弹层副标题全部改读视图；41 个元素 × 4 个用例逐字节一致 |

| 文件 | 迁移前 | 现在 | 剩余内容 |

# 国家／地区成长经历与模型修订方案

日期：2026-10-21。状态：考据及配置设计草案；没有修改游戏代码，没有运行游戏模拟。

## 1. 结论与范围

可行性高。现有游戏已有国家、种族、出生年、家庭、事件条件、次数限制、年龄抉择、组织联系人与年表，可承接此系统。主要工作是补齐地点、养育关系、制度资格和经历状态，而不是为每国重新编写引擎。

“地区专属”指只有符合当地制度或生活环境条件的人，才可能遇到某些具体经历，不保证所有当地角色遇到。学校、体育、手艺等活动可以跨国共用机制，但人物关系、制度、成本和后续路线应有当地特点。童年迁入者也可以经历当地生活；已经迁出的人不应继续接到只能现场参与的事件。

本轮交付：四个试点的可审核经历配置、其余现有出生地区的候选方案、国家模型修订清单、实现接口和验收标准。所有概率、年龄窗口、数值效果均为游戏设计，不冒充原作统计。

## 2. 证据使用规则

- **原文事实**：OCR 或 PRTS 收录的游戏文本实际写出的制度、设施、生活形态。
- **据此设计**：把上述事实转为玩家事件、选择、联系人和能力成长。事件年龄、频率、收益并非官方设定。
- **用户约定**：本作明确采用，但本轮没有找到足以证明其普遍性的原文。
- **待考**：不进入默认经历池，不凭熟悉感补成官方地名或制度。

### 拉特兰补充核验

核验页：[《众生行记／工坊日志》](https://prts.wiki/w/众生行记/工坊日志)，客户“莫斯提马＆菲亚梅塔”的“靶子”“葡萄干蛋糕”，以及客户“梵里妮”。

- 菲亚梅塔在综合射击课中有第一名记录，却因黎博利身份未列入毕业生守护铳制作名单；后续文本明确出现她的榴弹发射器。这支持共同训练、能力表现与守护铳资格分开设计。
- 按用户要求，默认角色成长路线中，守护铳资格限萨科塔；黎博利可接受武器训练，专属发射器路线止于榴弹发射器。这是本作采用的装备规则，不把个案文本扩写成“官方明确宣布全体黎博利的绝对技术上限”。榴弹发射器也不是整个武器系统中威力必然更低的一档。
- 黎博利制铳师指导萨科塔学徒并保管其母亲的守护铳，说明“有资格获得自己的守护铳”“制造、维护铳械”“保管别人的铳”必须区分。不得写成非萨科塔不能触碰、修理或保管守护铳。
- 共感另作种族能力；不因共同上学、共同训练或亲密关系而给黎博利添加共感。

## 4. 四个试点的具体配置

## 6. 配置与状态设计

### 地点与制度

逐步在现有 `nation` 外增加稳定的地点 ID、上级辖区、出生地点、当前位置、管辖政权、设施及有效年代。迁移只更新当前位置，出生地与成长历史保留。名称允许按年代变更，历史事件和出生生成共用同一地点记录。

每条经历配置至少包含：

| 字段组 | 内容 |
|---|---|
| 标识与展示 | 经历 ID、本地化标题、生活片段／主要背景／制度节点分类 |
| 来源 | 文件、chunk ID、文本种类、原文支持点、推演部分、证据置信度 |
| 范围 | 国家、地区、聚落、年代；使用出生地还是当前位置 |
| 资格 | 年龄、种族、学校／家庭关系、公民身份、设施、前置经历；必要条件不等于充分条件 |
| 排除 | 冲突经历、已经完成、设施停用、地域／年代不符 |
| 概率 | 条件池权重、阶段触发机会、冷却、终身上限；不与制度资格混淆 |
| 选择 | 玩家可选路线、照护者代为决定的低幼分支、资源消耗、退出条件 |
| 后续 | 联系人、训练记录、短期／长期效果、可解锁的学习与组织接触 |

状态独立保存：经历履历、成长标签、照护关系、学习／训练、身份与装备资格。生活片段不应强行占用唯一组织 `affiliation`；学校、养育所、厂区是生活关系，可以与成年职业组织共存。

### 抽取与延续

1. 确定年代及出生地域，选合法聚落，生成家庭、生活保障与种族。
2. 先确定养育安排，再按资格抽主要背景。没有专属背景仍是完整正常人生。
3. 在成长阶段提供当地机会；角色可以接触后退出，不预定成年职业。
4. 已建立的事实正常延续。例如入学以后，升学考核按规则出现；不能每年重新抽签决定此人是否曾经入学。
5. 年表变更、迁移、家庭变故后重新检查未执行机会，但不抹除已发生的经历。
6. 训练只在实际参与后累计；旁观设施不等于专业证照。求助联系人仅改善接触机会，不绕过既有组织招募要求。

建议同一时期最多一个需要玩家决策的成长主线节点，另配少量生活片段。主要养育背景在生成时最多一个；途中变更照护安排作为历史记录，不禁止人物一生经历多种家庭状态。

### 初版权重约定

资格过滤后，普通成长／无专属背景可先占一个独立基准权重，其余用低、中、高的相对档。不要把“权重 3”显示成“出现率 30%”。阶段总触发概率、不同资格人口占比和候选数量共同决定实际出现率。

先按事件数量预算做小样本观察，再按所有合格角色统计阶段累计率。原文中存在的基本制度不随趣味事件抽样而消失：例如学校确有课程、玩家已入学，是否弹出一次射击成绩故事与是否接受过该课程应分开。

## 7. 实现接入与规模

建议分四步实施，当前只列计划：

1. **先修数据模型**：地点实体与别名、年代、地区制度覆盖、生活保障、照护关系。保留旧 `nation` 等字段的兼容读取，明确地区人口是母国子集还是独立统计；不能直接改归属后重新加总人口。
2. **四试点**：落地本稿 18 项背景／阶段事件，复用已有矿区照护抉择。每项形成“接触—选择—后续”中的必要部分，不为凑数量强制写三段剧情。
3. **扩展其余地区**：每个地区先 1–2 条有足够来源的经历，优先补平民生活、教育与家庭体验。再增加地区／年代分支。
4. **验收与调参**：核对合法性、条件出现率、阶段累计次数、跨系统影响后再扩大事件量。

接入点：`state.js` 负责出生与关系状态；`nations.js` 和地点数据负责环境规则；`events.js` 的 `when`、权重、冷却和 `max` 可复用；`decision.js` 接成长节点；`year.js` 在实际执行前再次检查；`timeline.js` 共享地点和年代；组织引擎接收联系人与学习经历。需要增加统一资格判断，避免排入队列时合法、执行时已经迁出却仍发生的情况。

现有 [事件筛选](D:/terra-life/js/data/events.js:20)、[年龄抉择](D:/terra-life/js/engine/decision.js:147)、[矿区照护](D:/terra-life/js/data/decisions.js:404) 已提供部分能力；“不写新引擎”不等于纯文案工作。模型迁移和通用事件适配是中等规模改动，全国家内容主要成本是考据、分支文案与一致性验证。没有实作前不承诺精确工期。

旧存档只补缺失的中性字段，不凭空给成年人安排未曾发生的童年，也不更改已有父母生死。位置无法可靠识别的存档标记地区未知，保守跳过精确地方经历。

## 8. 验收设计（尚未执行）

### 必须为零的矛盾

- 黎博利因成绩优秀而获得自己的守护铳，或被禁止进入通用武器训练／工坊见习。

- 未在当地生活的角色亲历当地课程、参访；已经迁出却执行排队中的现场事件。

### 分布与故事效果

- 对四试点按年代、地区、种族、照护安排分层抽样；初轮每个主要合法组合约 1,000 个固定种子，稀有条件用定向样例验证，不为了等稀有事件盲目扩大样本。
- 同时报告合格人数、实际触发人数、阶段累计次数和未触发原因；不能只报全国平均率。

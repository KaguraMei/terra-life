# 存档版本协议

当前应用**只把已结束人生写成摘要**；完整人生的续存信封已经实现为协议与编解码器，
但尚未接入 UI 与存储端口。

存储键：

| 键 | 内容 | 说明 |
| --- | --- | --- |
| `terra-life:v1:completed-lives` | 死亡摘要数组 | 当前唯一写入的存档；每条带 `v: 1` 结构版本 |
| （未使用） | 完整人生信封 | 由 `src/model/save-envelope.ts` 定义，尚未持久化 |

`terra-life-saves-v1` 是重构前的旧键。本仓库不承诺读取它；`parseCompletedLifeRecords()`
仍能解析不带 `v` 的旧行并标记 `legacy: true`，只用于避免展示层崩掉。

## 已实现（可续存信封）

代码：`src/model/save-envelope.ts`；结构：`schemas/life-save-envelope.schema.json`；
验证：`tests/save-resume.test.mjs`。

- `serializeLife(state, context)` 产出 `{format, envelopeVersion, rulesetVersion, contentLock,
  createdAt, state, random, interactions}`。`queue` 与 `pending` 从领域状态中取出，
  单独放在 `interactions`，因为它们需要独立的迁移策略。
- **只写 JSON**。函数、循环引用、非有限数字、数组空洞都会带路径报错（`SaveSerializationError`），
  不做静默丢弃；`pending._def/_opts` 这类运行时句柄永远不进入信封。
- **待决抉择**只存稳定定义 ID + 选项快照（index/label/hint/hidden）。恢复时重新解析定义与可用选项，
  数量或标签对不上就拒绝恢复，而不是让玩家面对另一个问题。
- **随机状态**存 `algorithm` / `version` / `seed` / `state` / `draws`。只有种子无法恢复中途随机流；
  未播种的自然熵不可续存，`randomSnapshot()` 返回 `null`，序列化会直接拒绝。
- **读档顺序**：`migrateLifeEnvelope()`（版本迁移链，当前只有 v1，未知版本显式失败）→ 结构校验 →
  规则/内容版本匹配 → 恢复随机 → 状态不变量。失败抛 `SaveEnvelopeError` 且不修改输入对象。
- **内容锁**：`contentLock.packages` 记录本局依赖的每个题包 `{id, version, hash}`（`src/content/pack-lock.ts`）。
  `hash` 是内容身份校验和（FNV-1a over 规范化投影），**只覆盖会改变"玩家被问什么/怎么算分"的部分**
  —— 题 ID、选项 ID、分数向量、题池装配与及格线；题面文案、注释、声明顺序都不进摘要，
  所以改文案不会让旧存档失效。
- **已结束人生**不走信封（`state.phase === 'report'` 会被拒绝），进入摘要存储，两种能力分开。

## 自动存档策略（当前实现）

- **单槽**：`terra-life:v1:resumable-life`，只保留一局进行中的人生。
- **存档点**：`endYear` 年度结算**提交之后**（此时 `t` 已归零、下一年队列已排好）。年份中途、待决抉择未落地、
  派发事务未提交时不写盘 —— 存档只发生在已提交的边界上。
- **清理**：死亡（`die`）与开新局（`newLife`）都会删槽，避免"继续"指向已结束或已被取代的人生。
- **每局都有确定种子**：不带 `seed` 的新局会在创建时钉一个随机 32 位种子。没有种子的局无法复现、
  也就无法续存，所以"随机"在这里等于"替你抽了一个种子"，而报告里能看到它。
- **成本**：每年一次 JSON 往返；没有可用存储端口时整条路径短路（连序列化都不做）。
- **失败不打断**：序列化失败只上报（`[save] …`）并保持游戏继续，绝不写半份存档。

## 内容不匹配的诊断码

读档时把内存里的题包清单与信封记录逐条比对（`restoreLife(..., {packages})`），任何一条不符都**拒绝恢复**
并给出可定位的码，而不是猜"大概是同一套题"：

| 码 | 含义 |
| --- | --- |
| `content.package-missing` | 信封里的题包在这个构建里不存在 |
| `content.package-version-changed` | 同 id 但版本号不同（内容已更新） |
| `content.package-content-changed` | 版本号相同但内容摘要变了（改了却没升版本） |
| `envelope.package-duplicate` | 信封把同一个题包列了两次 |
| `envelope.package` | 条目缺 id/version/hash 或不是对象 |

**面试会话自带出处**：开始面谈时把 `{id, version}` 记进 `session.pack`，题目与选项是**快照拷贝**而非引用，
因此进行中的面试不受题包更新影响；存档恢复后会话仍带着同一出处，答完后结果（status / score / pool）
与不中断的一局完全一致。

## 已验证

- 连续运行 vs「运行到 40 岁 → 存档 → 新运行时恢复 → 继续」：领域状态哈希、后续随机流尾、最终结局一致。
- **年度边界续存**：跑到第 5 个年度结算 → 新运行时读槽 → 状态哈希与随机流尾一致 → 续跑到死亡与原局逐字节相同。
- 抉择进行中存档：恢复后待决抉择 ID 与选项标签一致，选择同一项后状态与连续运行一致。
- 版本不匹配（ruleset / core）拒绝恢复；损坏或陌生信封返回诊断而不是猜测。
- 摘要读取：当前键与旧键都能解析，损坏行被丢弃，输入数组不被改写。
- 死亡清槽、开新局清槽、无存储端口时时整条自动存档路径为惰性（不影响模拟结果）。

## 迁移链

`ENVELOPE_MIGRATIONS[版本] = (raw) => 升级后的信封`，链式执行到 `SAVE_ENVELOPE_VERSION`。
加一步时的规矩：

- 步骤必须**只做结构升级**，不猜内容；升级后仍要过 `validateLifeEnvelope`。
- 步骤必须把 `envelopeVersion` 往前推。为了防"忘了加版本号导致死循环"，链条有 32 步上限，
  超限报 `envelope.migration-loop`。
- 没有对应步骤的版本直接 `envelope.version-unsupported`，不做任何"看起来像"的兼容。

`migrateLifeEnvelope(input, migrations?)` 的第二个参数可注入，所以链条本身可以在**没有真实历史版本**时
被测试：`tests/save-resume.test.mjs` 用一份伪造的 v0 信封（`contentLock` 还没有 `packages`）验证
"拒绝 → 加步骤后可迁移 → 迁移结果能通过校验并真的恢复 → 不推进版本的步骤被拦下"。

## 尚未实现

- **多槽位 / 命名存档 / 手动存档点**：当前只有自动单槽，也没有"存档导出/导入"。
- **跨版本容忍策略**：现在题包一变就拒绝恢复（fail closed）。会话本身是自包含快照，理论上可以容忍
  "只有本次会话所用的包变了"，但那需要按会话维度做豁免，且要先证明计分不依赖新包，暂不做。
- 迁移链目前**没有真实历史版本**（v1 就是第一版）；机制已可测（见上节），但第一份真实信封格式变化
  发生时仍要补一条"旧信封 → 新信封"的回归。

## 约束（不要违反）

- 不把运行时对象、闭包、DOM 节点、原型链或 UI 临时状态写进存储。
- 不在事务未提交时保存（转换守卫 `commit()` 结束后才允许序列化）。
- 恢复失败保留原始数据；缺包时不静默删除人物或任务。
- 快照只允许在领域转换提交完成后生成。

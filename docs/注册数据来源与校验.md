# 注册数据来源与校验

核心组织、职业、种族、国家、年表、事件与抉择仍由 JS 手写维护；装配完成后统一附带 `provenance`：

- `setting.kind` 表示来源性质：可核验设定、参考资料、项目整理/创作、项目模型，或待补的一手来源。
- `setting.confidence` 表示记录对设定依据的把握；`setting.sources` 给出可追溯入口。
- `gameModel.kind` 与 `gameModel.sources` 单列游戏中的数值和规则推断。职业薪酬区间、触发权重、个体效果等不应被当作官方事实。
- 元数据结构见 [content-provenance.schema.json](../schemas/content-provenance.schema.json)。组织字段先例见 [organization.schema.json](../schemas/organization.schema.json)。

目前国家人口参数、种族修正、职业收益/风险、事件概率和部分年表叙述只有项目内来源；记录会以 `reference-needed` 或 `project-reconstruction` 明示，不能把项目文档误写成外部设定证据。组织保留逐条 `source`、`sourceType`、`confidence`，招募/晋升/薪酬另由项目规则文档说明。

## 校验器

运行时校验在 `src/content/registry-validation.ts`，每次装配都会执行；失败终止启动，不静默覆盖注册表。
它返回结构化诊断 `{code, path, message}`（`formatDiagnostics()` 负责渲染），因此测试断言的是
**故障类型**而不是文案。

| 域 | 已检查 |
| --- | --- |
| 国家 / 种族 | ID 唯一、来源可追溯、`race`/`where` 互相引用存在、`NATION_BY_ID`/`RACE_BY_ID` 索引大小一致 |
| 组织 | 来源性质与置信度、`rulesSource`/`yearBasis`、`fromYear`/`untilYear`/`recruitUntil` 窗口、雇佣模型存在、辖区国家存在 |
| 组织路线 | 名称、`minAge`、`jobs`/`entryJob` 引用、`ranks` 非空且 `needYears` 单调 |
| 组织联系人 | ID 唯一、`chance ∈ [0,1]`、人物窗口不倒置 |
| 职业 | 名称、`lo ≤ hi` 且非负、`edu/art/ori/disc` 完整、风险乘数非负、`only`/`notNations` 引用存在 |
| 事件 | 注册键与 `id` 一致、权重非负、`max` 为整数、`cd` 非负、年份窗口不倒置、`organization` 引用存在 |
| 年表 | `year` 为整数、`scope.nations` 与 `fx` 键引用存在、个体死亡概率在 `[0,1]` |
| 抉择 | 标题存在、选项非空、选项标签存在、`eff` 全为有限数、`when` 必须是函数 |
| 来源注册表 | `version` 为 1，每个域都有 `facts` 与 `inference` 条目，条目含 `source` 与 `scope` |

## 演进方向

JSON Schema 文件仍是编辑器与外部包校验的权威描述，运行时用这份零依赖校验器执行同一套关系。
外部 DLC 解析后必须经同一校验器（M3 的注册器会复用），不能为"外来数据"另开一条宽松路径。

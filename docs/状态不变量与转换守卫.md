# 状态不变量与转换守卫

`S` 是跨模块共享的可变对象，组织归属、职业身份、退休、养老金、矿石病与收支之间存在联动。
本文件记录**当前实现**把这些联动集中在哪里、用什么方式检查，以及哪些行为已经被回归固定。

代码位置：

| 责任 | 文件 | 说明 |
| --- | --- | --- |
| 不变量定义 | `src/model/state-invariants.ts` | 只描述关系，不重算任何模型数值 |
| 提交守卫 | `src/model/transitions.ts` | 转换执行后统一复核，失败即中止 |
| 装配接入 | `src/legacy/create-runtime.js` | 组织/退休入口统一包装，并声明年度管线的一次性延迟 |
| 资格入口 | `js/engine/organization.js` | `canBeDismissed` / `dismissFromJob` / `enterCoercedLabour` |

## 诊断码

每条违规都有稳定 `code` 与点号 `path`，测试断言行为而不是匹配文案。

| code | 关系 |
| --- | --- |
| `identity.affiliation-requires-job` | 在职时 `job` 必须等于组织登记的 `orgJob` |
| `identity.affiliation-unknown-organization` / `-route` | 归属组织与路线必须存在 |
| `identity.unknown-job` | `job` 必须是注册职业或公认的非工作状态 |
| `career.open-history-mismatch` | 在职时恰好一条未闭合履历，且组织/路线一致 |
| `career.departure-history-open` | 已离职时不能残留未闭合履历 |
| `career.history-partial-close` | 履历的 `leftAt` 与 `leftYear` 必须同时闭合 |
| `career.retired-flag-job-mismatch` | `flags.retired` 为真时 `job` 必须是 `retired` |
| `career.retired-job-flag-mismatch` | `job` 为 `retired` 时必须有退休旗标 |
| `career.retired-marked-seeking` | 已退休个体不能被改写成待业 |
| `career.retired-retains-affiliation` | 已退休个体不能保留在职归属 |
| `pension.amount-invalid` / `pension.without-retirement` / `pension.organization-unresolved` | 养老金金额合法、随退休身份存在（或明确标注停发）、能追溯到授予组织 |
| `pension.suspended-while-retired` / `pension.suspension-invalid` | 停发只在失去退休身份时成立，且必须记录停发年龄 |
| `economy.field-not-finite` | `money`/`debt`/`income` 保持有限 |
| `health.stage-out-of-range` / `health.crystal-out-of-range` | 分期 1–3、结晶率 0–100 |
| `career.rank-invalid` / `career.service-invalid` | 等级与任职年限非负 |

## 转换守卫

`createLifeGuards(registry).commit(name, state, action, options?)` 在动作执行后复核全部关系：

- 违规抛出 `StateInvariantError`，消息包含转换名与违规清单，便于定位"是哪一步写坏的"。
- `options.deferred` 声明**本次提交内**合法但短暂的关系，例如年度管线把退休拆成
  "改身份 → 时间线 → 组织退出"，中间态允许 `career.retired-retains-affiliation` 与
  `identity.affiliation-requires-job` 短暂成立；其他违规仍然失败。
- 守卫**不修复**状态。修复责任属于字段所有者。

纳入守卫的入口共 8 个：

| 类别 | 入口 |
| --- | --- |
| 组织身份 | `joinOrganization` / `leaveOrganization` / `syncOrganization` / `retire` |
| 个体状态 | `infect` / `die` / `dismissFromJob` / `enterCoercedLabour` |

### 上闸时被抓到的三个真问题

把 `infect` / `die` / `dismissFromJob` / `enterCoercedLabour` 也纳入守卫之后，用固定种子跑 1000 局
（292000 与 970000 两段）立刻暴露出旧逻辑一直在写坏状态：

1. **被辞退的组织成员保留归属**：`dismissFromJob` 只把 `job` 改成 `seeking`，`affiliation` 与 `orgJob`
   原封不动，违反 `identity.affiliation-requires-job`。现改为：组织成员被辞退时走 `leaveOrganization`，
   履历以「被辞退」闭合，并照常进入冷却。
2. **退休金成为孤儿**：退休者被押去劳役后 `flags.retired` 被清空，但 `retirementPension` 原样留着，
   违反 `pension.without-retirement`。现改为：劳役时把退休金标注 `suspendedAt`（记录仍在，明确停发），
   重新获得退休身份时清除标注并写 `resumedAt`。
3. **劳役与组织身份并存**：组织成员被押走时同样会留下无岗位的归属，现同样先结束组织身份。

这三处都属于"状态自相矛盾但没人检查"，修完后 1000 局零违规、分布不变（`mean 52.904` / `p 50 → 46` /
感染率 `0.165` / 任职 286 段与归档基线一致）。

## 已固定的行为边界

回归 `tests/model-regression.test.mjs`、`tests/state-contract.test.mjs` 与
`tests/identity-transitions.test.mjs` 断言：

1. 退休个体不会被普通事件或 `ori_job_loss` 抉择辞退（资格判定 + 抉择不再出现 + 正向对照）。
2. 强制劳役（苦役/服刑）**取代**退休身份与组织身份，而不是叠加；退休金随之停发而非消失；
   重新退休时恢复同一份退休金；释放后回到退休前职业。
3. 组织加入/离开/同步/退休、感染、死亡、失去职业、强制劳役全部通过守卫提交，离职履历闭合，
   退休不再计在职薪酬。
4. 1000 局固定种子人生逐局通过全部不变量。

## 直写清单的棘轮

守卫只在被调用的那一刻复核；内容直接写 `S.job = ...` 依然可以绕过。为了不让这种直写**继续增长**，
`tools/scan-state-writes.mjs` 把当前内容层的直写按「文件 × 字段」冻结成
`docs/data/state-writes.json`（现为 **331 处**），并接入 `npm run verify`：

```bash
node tools/scan-state-writes.mjs          # 列出账本
node tools/scan-state-writes.mjs --check  # 任何一处增加就失败，减少会打印出来
node tools/scan-state-writes.mjs --write  # 迁移后重新记录（需说明原因）
```

失败信息直接给替代路径：`TL.applyEffects`（属性/现金/旗标）或守卫入口
（`dismissFromJob` / `enterCoercedLabour` / 组织与退休转换）。引擎内部的合法写入（`year.js`、
`organization.js`）也在账本里，只是不再允许变多——重构把代码搬走时数字下降，正是迁移的进度条。

## 边界与后续

- 守卫在转换点拦截，但**不**阻止内容直接写 `S.job`；棘轮 + 回归批量运行是第二道网。已落地的两半是
  [事件效果契约](事件效果契约.md)：新内容用 `TL.applyEffects()` 提交声明式变更（白名单里没有
  "改职业/加组织/退休/感染"，因此绕不过守卫），调度层则在派发失败时整份回滚状态与随机流。
  剩余直写按账本逐个迁移并做等价证明。
- 事件层仍用 `run(S)` 旧接口（直接改状态），因此"不变量通过"不等于"字段级事务完成"：
  回滚粒度是"整份派发"，不是"单条效果可撤销"。
- 规则版本变更后，先看 `npm run regress:model` 的分布，再决定是否调整
  `docs/data/model-baseline.json` 的区间；区间是护栏，不是平衡目标。
